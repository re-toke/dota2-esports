# PRD：首页改版与 TabBar 精简（UI v2）

- 日期：2026-08-30
- 状态：待评审（先出 PRD + 原型图，未实施）
- 原型图：`mockup/home-v2-mockup.html`

## 1. 背景与目标

当前 5 tab（首页/赛事/战队/我的/资料库）信息冗余，首页快捷入口与 tab 功能重叠；首页仅有「我的关注」卡片与「为你推荐」赛事卡，缺少全量比赛数据流；真机测试中底部安全区上白色系统提示线与暗色背景对比突兀。

**目标：**
1. TabBar 5 → 3，释放导航空间，降低切换噪音。
2. 首页从「推荐页」转型为「数据中枢」：全量比赛流 + 周日历时间轴。
3. 底部安全区与页面背景无缝衔接，消除白色突兀感。

### 4.1 周日历时间轴（新增组件 `week-calendar`）

- 横向 7 格：周一～周日 + 日期数字；今天高亮（暗金 `#C8A951` 底、深色字）。
- 有比赛的日期下方显示**数字角标**（当日比赛场次数）：金色 `#C8A951` `22rpx`（`--fs-caption` 档，复核修订：原文 11px 与项目 rpx token 体系不一致）半粗 tnum 数字，今天格内反色为深色；无比赛的日期不显示。数字清晰传达比赛密度，无需用户学习图例。
- 默认选中「今天」；左右滑动/点击切换，支持跨周切换（「‹ 上周 / 下周 ›」箭头或滑动到边缘自动翻页）。
- 数据来源：复用赛事聚合（OpenDota proMatches + 云端 aggregation + upcoming-local），按本地时区日期分桶。
- 选中日期无比赛 → 显示空态卡（"该日暂无对局，看看其他日期吧"）。

### 4.2 全量比赛流（新增组件 `match-flow`）

- 状态筛选 chips 与周日历联动，默认选中「全部」（LIVE 置顶排序：进行中 > 即将开始 > 已结束）。
- **进行中（LIVE）**：红点脉冲 + 实时比分，倒计时入场提示。
- **即将开始**：开赛倒计时（"2 小时后"）。
- **已结束**：终局比分 + 胜方标记（沿用 `--radiant` / `--dire` 语义色）。

比赛卡片字段（对齐 match-detail 现有字段）：

```
┌──────────────────────────────────┐
│ [等级标签] 赛事名（纯文字）   BO3  │
│ ┌────┐  ┌────────┐  ┌────┐      │
│ │logo│  │ 2 : 1   │  │logo│      │
│ │简称│  │ 比分/倒计时│  │简称│      │
│ └────┘  └────────┘  └────┘      │
│ 胜方高亮 · 时长/开赛时间 · › 详情  │
└──────────────────────────────────┘
```

- 赛事名前不加 LOGO 图标，保持纯文字（等级标签 S/A 为文字徽章，保留）。

- 战队 logo 沿用 Liquipedia + image-fallback 组件（域名已在合法列表）。
- 点击卡片 → `subpackages/detail/match-detail`。
- 阶段判定沿用既有 6 小时回退规则（未标记 finished 且开赛超 6 小时 → 已结束）。
- 分页/懒加载：首屏 6-8 场，滚动加载；进行中比赛 60s 轮询刷新比分（可降级为手动下拉刷新，评审时定）。
- **轮询健壮性（复核新增）**：仅 tab 页可见时轮询（onShow 启动 / onHide 停止）之外，增加失败指数退避 60s→120s→300s 封顶，失败静默（不打断 UI，不弹 toast），恢复成功后回归 60s。避免网络异常/OpenDota 免费档限频（60 req/min）时空转。
- **比分变化反馈（复核新增）**：轮询致比分数字变化时，该格做 300ms 亮金渐隐闪光（`--dota-gold` 背景淡出），传达「数据是活的」。实现用 wxss keyframe + `data-flash` 类切换，`prefers-reduced-motion` 降级为无闪光。

## 5. 底部安全区改进（R1）

现状：`.tab-bar` 整体 `rgba(13,13,13,0.92)` + backdrop blur；真机 iPhone Home 指示条为白色（iOS 系统行为，无法直接改色），在半透明底上对比强烈。

方案（两步）：
1. `.tab-bar` 安全区段改**不透明纯色** `#0a0a0b`（或与页面背景 `#0d0d0d` 同值），与页面背景无缝衔接；tab 内容区可保留毛玻璃（视觉分层：内容区微透、安全区实底）。
2. 保持 `app.json` `backgroundColor: #0d0d0d` 不变，确保非 tab 页滚动到底部时同样衔接。

效果：白色 Home 指示条仍在（系统限制），但底色统一为纯深色后视觉上融入整体暗色调，突兀感显著降低。原型图中含 before/after 对比帧。

## 9. 跨页面设计系统清扫（并入本次交付的独立批次）

背景：逐页审计（2026-08-30）发现各页面结构无需大动，但存在三类系统性不一致。本批次与首页改版解耦、可并行，验收独立。

### 9.1 灰阶收敛（四档制）

现状：178 处、约 10 种灰值散落 20 个 wxss 文件。收敛为四档并 token 化：

| Token | 值 | 用途 | 被收敛的散值 |
|---|---|---|---|
| `--text-1` | `#f0f3f6` | 主文字 | —— |
| `--text-2` | `#8a8f99` | 次要文字 | `#9ca3af` `#9aa4b2` `#7d8794` `#8b949e` `#98a0ab` `#9bb0c9`* |
| `--text-3` | `#6b7280` | 已结束/新鲜度/装饰 | 直接 token 化引用 |
| `--text-4` | `#5b626d` | 占位/禁用 | 直接 token 化引用 |

*`#9bb0c9` 为偏蓝灰（来源溯源 curation 徽标专用色），保留为 `--source-curation`，不并入 `--text-2`。

**与 TDesign 灰阶的整合（复核新增）**：app.wxss 已有 `--td-text-color-primary/secondary/placeholder/disabled` 四档灰，直接覆写这四个 `--td-*` 变量的值指向上表 token（页面现有大量 `--td-*` 引用自动继承），`--text-*` 仅作别名定义，避免出现第三/四套并行 token 造成「越收敛越多」。

重灾区（按替换量）：`subpackages/detail/league-detail`（33 处）、`pages/leagues`（32 处）、`pages/follow`（17 处）、`pages/teams`（11 处）。

| 语义 | Token | 动作 |
