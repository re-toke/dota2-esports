### 2.2 ⚠️ 需降级或改述（2 项）

#### 【P1-9 live 去重 key 错位】⚠️ 缺陷成立，但**级别偏高、影响面夸大**

**缺陷本身**：键错位（写 `length`、push `length-1`）是**确凿的代码错误**，复核无异议。

**但触发条件被原报告低估了门槛**。复核读了 `_pairKeyX` 的实现：
```js
// utils/sources.js:2524-2538
function _normTeamX(s) {
  if (!s) return '';                    // ← 队名缺失/空 → 返回空串
  ...
}
function _pairKeyX(m) {
  var a = _normTeamX(m.team1Name || m.radiant_team_name);
  var b = _normTeamX(m.team2Name || m.dire_team_name);
  if (!a || !b) return null;            // ← 两者任一为空才走 standalone 分支
  ...
}
```
要触发该分支，必须**某场的两个队名字段双双为空/缺失**。注意反直觉的一点：`"TBD"` 归一化后是 `"tbd"`（非空），**不会触发**。真正触发需要上游数据异常（字段整体缺失）。

→ **建议降为 P2**。分级标准中 P1 要求「有明确触发条件，用户可感知」，而此处属「数据异常时才触发的隐患」，符合 P2 定义。

**影响面也需收窄**：原报告称「首页『进行中』段整段消失」。复核了调用位置：
```js
// pages/index/index.js:573-574（位于 _fetchLpUpcoming 内）
const upSeries  = sources.buildLpUpcomingSeries(upMs, now);
const liveSeries = sources.buildLpLiveSeries(liveMs, now);   // ← 若此句抛错
```
`buildLpLiveSeries` 抛错 → 整个 `_fetchLpUpcoming` reject → `.catch(() => [])` → **upcoming 与 live 一并丢失**。但**② /live 段（OpenDota 直连）与 ④ proMatches（已结束）不受影响**，仍在渲染。

→ 准确表述应为：「**⑥ 段由 LP/Steam 提供的对局卡（live + upcoming）全部丢失**；② /live 段与已结束段仍正常」。

#### 【P1-10 EF 熔断器】⚠️ 缺陷成立，但**影响面严重夸大**

**缺陷本身**：无 TTL、无半开、不分桶——复核确认，且与项目另两套熔断器（`cloudBreaker` 有 TTL、`haglund` 有 HALF_OPEN）的不一致也确认。

**但「全站数据链路中断」是错的**。复核发现 `efAvailable()` 只在**一处**被调用：

```js
// utils/supabaseClient.js:37（在 edge() 内）
if (!efAvailable()) { reject(new Error('supabase ef unavailable')); return; }

// utils/supabaseClient.js:85-87（rest 函数，直连 PostgREST）
function rest(table, query) {
  return new Promise(function (resolve, reject) {
    if (!enabled()) { reject(...); return; }      // ← 只检查 enabled()，不检查 _efBreakerOpen
```

即：**EF 熔断不影响 `rest()`（PostgREST 直读）通道**。而 `remoteCuration` 的 curation 读写走的正是 `sb.rest()`（`remoteCuration.js:152`）。

→ 准确表述应为：
> 「EF 熔断后，所有经 Edge Function 的 action（联赛列表、OpenDota 代理、Liquipedia/Steam/haglund 赛程、聚合 bundle、登录鉴权、订阅）整会话不可用；但 **PostgREST 直读链路（curation 表）不受影响**。云函数下线后，EF 成为这些 action 的唯一后端 → 熔断即**这些链路**全断（**并非"全站"**，curation 仍可用）。」

**级别判定**：原报告列为 P1 是合适的（观察期有云函数兜底），修正的只是影响面描述。

## 七、复核方法论沉淀

### 7.1 本次复核最有效的三个手段

1. **「权威源 vs 二手口径」对读**
