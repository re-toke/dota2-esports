## 1. 问题描述

在赛事详情页的「对阵」模块中，LIVE/UPCOMING/RECENT 三段对局的 BO 赛制判定存在错误。以 **1win Essence II** 为例：

- 截至 2026-08-03 00:30（北京时间），该赛事所有比赛均为小组赛阶段
- 小组赛全部采用 **BO2（双局积分制）** 赛制（Format 说明明确标注："All matches are {{Abbr/Bo2}}"）
- 但赛事详情页中：
  - **RECENT 段**（OpenDota 数据）：比赛显示为 **BO3**（误判）
  - **UPCOMING/LIVE 段**（Liquipedia 数据）：比赛显示为 **BO1**（误判）

## 2. 现有方案（v2）的逻辑问题回顾

### 问题 1（★ 致命）：`parseMatchFields()` 中 `section` 尚未赋值即被引用

**v2 方案的核心缺陷**：v2 方案在 `parseMatchFields()` 内部使用 `fields.section` 进行 phaseBOMap 查找，但实际代码中 `fields.section` 是在 `parseMatchFields()` **返回之后**才赋值的。

**当前代码执行顺序**（`liquipedia-parse.js` 第 526-530 行）：

```javascript
var fields = parseMatchFields(body);     // ① 调用 parseMatchFields
                                         //    fields.section 尚未存在
if (!fields) continue;
fields.section = currentSection;         // ② 在此处才设置 section
```

**v2 方案错误地假设了**：

```javascript
function parseMatchFields(body, phaseBOMap) {
  // ...
  if (bo == null || isNaN(bo) || bo < 1) {
    if (phaseBOMap && fields.section) {  // ← ❌ fields.section 永远为 undefined
      // ...
    }
  }
}
```

**影响**：v2 方案的 Format 节解析 → 阶段推断机制完全失效，所有 `bestof` 缺失的 Match 模板仍被默认判定为 `BO1`。

**正确修复方式**：将 `currentSection` 作为独立参数传入，而非依赖 `fields.section`：

```javascript
var fields = parseMatchFields(body, phaseBOMap, currentSection);
```

### 问题 2：`parseFormatBO()` 的 Format 节正则容错性不足

v2 方案的 Format 节正则：

```javascript
var fmtMatch = wikitext.match(/==\s*Format\s*==\s*\n([\s\S]*?)(?=\n==|$)/);
```

缺陷：
- 要求 `==Format==` 和内容之间**必须紧随换行符**，不能有空行
- 但 1win Essence II 的 Format 节内容中 "*'''Group Stage'''..." 与 `==Format==` 标题之间实际有一行空行间隔
- 部分 Liquipedia 页面可能使用 `==Format==` 后直接跟内容的格式，也可能有多个空行

**v3 改进**：
- 使用 `\s*` 替代 `\n`，兼容任意空白符（空行、空格等）
- 使用 `\n==[^=]` 替代 `\n==`，正确匹配下一个二级标题 `==Group Stage==`（`[^=]` 确保不是 `===` 子节）

```javascript
/==\s*Format\s*==\s*([\s\S]*?)(?=\n==[^=]|$)/
```

### 问题 3：`groupSeries()` 的 BO2 判定逻辑过度依赖 `series_type === 0`

当前代码（`sources.js` 第 887-895 行）：

```javascript
} else if (maxScore === 2) {
  if (st === 0 && totalGames === 2) {
    boType = 'BO2';
  } else {
    boType = 'BO3';
  }
}
```

缺陷：
- `st === 0` 是严格等于，`st = null` 或 `st = undefined` 时条件不成立 → 误判为 `BO3`
- 1win Essence II 的 OpenDota 数据中 `series_type` 很可能为 `null`，导致 BO2 被误判为 BO3

**v2 方案的修复**：将条件改为 `totalGames === 2 && maxScore === 2`，但移除了 `st === 0` 的守卫。这引入了新的问题：当 `series_type=1`（明确标记 BO3）但只打了 2 场（2-0 横扫）时，如果 `st === 1` 分支未拦截（因为放在了 BO2 分支之后），则会被误判为 BO2。

**v3 方案的正确修复**：保持 `st === 1` 分支优先于 BO2 分支，确保明确标记的 BO3 不受影响。

### 问题 4：交叉校正仅覆盖 BO3→BO2 单向

v2 方案只处理了 OpenDota 判定为 BO3 而 Liquipedia 为 BO2 的场景。但未覆盖：
- OpenDota 因 `series_id` 缺失将 BO2 拆分为 2 个独立 BO1 系列
- OpenDota 因 `series_type` 不匹配将 BO2 判为 BO5 等极端情况

**v3 方案**：保留方案 D（场景关联匹配），并增加 `series_id` 检测诊断日志。

### 问题 5：Liquipedia 数据源本身数据稀疏

1win Essence II 的 Group Stage 赛程中，大部分 `{{Match}}` 模板为空（无 opponent/date 字段），`parseMatchFields()` 会返回 `null` 并跳过。这意味着即使 Format 节解析成功，Liquipedia 来源的 UPCOMING/LIVE 段也可能没有足够的数据来显示对阵。

**影响**：UPCOMING/LIVE 段可能没有足够的数据点来展示 BO 标签。但这是数据源本身的限制，需要通过其他手段（如 OpenDota 数据）补充。

## 3. 修正后的根因分析

### 根因 1（★ 核心）：Liquipedia {{Match}} 模板缺少 `bestof` 字段

- 1win Essence II 小组赛的 `{{Match}}` 模板均未设置 `|bestof=2`
- 当前 `parseMatchFields()` 在 `bestof` 缺失时默认 `bo = 1` → `BO1`
- **影响范围**：所有 Liquipedia 来源的赛程中，未在 Match 模板显式设置 bestof 的赛事
- **v2 方案的修复路径正确但实现有 bug**（section 未赋值问题）

### 根因 2：OpenDota `series_type` 对 BO2 无对应值

- OpenDota 的 `series_type` 枚举值：0=BO1, 1=BO3, 2=BO5
- BO2 没有专用值，可能返回 `null`/`undefined`
- 当前代码 `st === 0` 的严格等于条件排除了 `null`
- **影响范围**：所有 OpenDota 有数据且使用 BO2 赛制的赛事

### 根因 3：BO2 两场比赛可能不共享 `series_id`

- OpenDota 可能给 BO2 的两场比赛分配不同的 `series_id`（或 `series_id = 0`）
- 无 `series_id` 的比赛各自独立成组 → 被判为 BO1
- **影响范围**：OpenDota 数据中 `series_id` 缺失或分配不正确的 BO2 赛事

### 根因 4：Format 节信息未被利用

- Liquipedia 的 Format 节包含完整的赛制说明（阶段名→BO 类型映射）
- 当前代码完全未解析 Format 节
- v2 方案尝试利用但存在实现缺陷
- **影响范围**：所有依赖 Liquipedia 赛程的赛事，当 Match 模板缺少 bestof 时

## 4. 修正后的优化方案

### 总体架构：四层递进判定（修正版）

```
Layer 1: Format 节解析（liquipedia-parse.js）
  → 从 Format 节提取 phase→BO 映射
  → 如 { "Group Stage": "BO2", "Playoffs": "BO3", "Grand Final": "BO5" }

Layer 2: Match 模板解析 + 阶段感知 BO 推断（liquipedia-parse.js）
  → 解析 {{Match|bestof=...}} 模板
  → bestof 缺失时，用 currentSection 匹配 Layer 1 的映射（★ 关键修正：传入 currentSection 而非依赖 fields.section）
  → 仍未匹配则默认 BO1

Layer 3: OpenDota groupSeries 判定（sources.js）
  → 修复 series_type null 时的 BO2 判定
  → 优先使用 series_type=1 明确标记的 BO3
  → 2 场比赛 + 2-0/1-1 → BO2（但需 st!==1 守卫）

Layer 4: 跨源交叉校正（league-detail.js）
  → 用 Liquipedia 的 BO 类型（Layer 2 产出）校正 OpenDota 的 RECENT 数据
  → 仅校正 BO3→BO2 方向，避免误校正
```

### 方案 A（必做）：Format 节解析 + 阶段感知 BO 推断（★ 修正 v2 实现缺陷）

**目标**：从 Liquipedia 的 Format 节提取 phase→BO 映射，用于 `{{Match}}` 模板 `bestof` 缺失时的兜底。

#### A1. 新增 `parseFormatBO()` 函数（`liquipedia-parse.js`）

```javascript
/**
 * 从 Format 节 wikitext 中提取 phase→BO 类型映射。
 * 
 * 解析规则：
 *   1. 定位 ==Format== 节
 *   2. 扫描所有粗体阶段名（'''X'''），如 '''Group Stage''', '''Playoffs'''
 *   3. 在阶段名后查找 {{Abbr/BoN}} 或 "BoN" 模式
 *   4. "All matches are BoN" → 该阶段所有比赛均为 BoN
 *   5. "Grand Final is Bo5, all other matches are Bo3" → 细分规则
 *
 * v3 修正：
 *   - 正则更宽松：允许标题与内容间有任意空白行
 *   - 限制阶段名扫描范围：仅扫描 Format 节内的粗体文本，排除外部误匹配
 *   - 返回 { phaseName: boType } 映射或 null
 */
function parseFormatBO(wikitext) {
  if (!wikitext) return null;
  try {
    // ★ v3 修正：允许标题与内容间有任意空白（\s*），而非强制 \n
    var fmtMatch = wikitext.match(/==\s*Format\s*==\s*([\s\S]*?)(?=\n==[^=]|$)/);
    if (!fmtMatch) return null;
    var fmtText = fmtMatch[1].trim();
    if (!fmtText) return null;
    
    var phaseMap = {};
    // 扫描阶段名：'''Group Stage''' 或 '''Phase Name'''
    var phaseRegex = /'''([^']+)'''/g;
    var phases = [];
    var match;
    while ((match = phaseRegex.exec(fmtText)) !== null) {
      phases.push({ name: match[1].trim(), index: match.index });
    }
    
    // 对每个阶段，在其后查找 BO 信息
    for (var i = 0; i < phases.length; i++) {
      var p = phases[i];
      var startIdx = p.index;
      var endIdx = (i + 1 < phases.length) ? phases[i + 1].index : fmtText.length;
      var block = fmtText.substring(startIdx, endIdx);
      
      // 规则 1: "All matches are BoN" 或 "all matches are BoN"
      var allMatch = block.match(/all\s+matches\s+are\s+(?:{{Abbr\/)?Bo(\d+)/i);
      if (allMatch) {
        phaseMap[p.name] = 'BO' + allMatch[1];
        continue;
      }
      
      // 规则 2: "Grand Final is Bo5, all other matches are Bo3"
      var gfMatch = block.match(/grand\s+final\s+is\s+(?:{{Abbr\/)?Bo(\d+)/i);
      var otherMatch = block.match(/all\s+other\s+matches\s+are\s+(?:{{Abbr\/)?Bo(\d+)/i);
      if (gfMatch && otherMatch) {
        phaseMap[p.name] = 'BO' + otherMatch[1];  // 非总决赛的默认赛制
        phaseMap['Grand Final'] = 'BO' + gfMatch[1];
        continue;
      }
      
      // 规则 3: 兜底 — 查找任何 "BoN" 模式
      var boFallback = block.match(/Bo(\d+)/);
      if (boFallback) {
        phaseMap[p.name] = 'BO' + boFallback[1];
      }
    }
    
    return Object.keys(phaseMap).length ? phaseMap : null;
  } catch (e) {
    return null;
  }
}
```

#### A3. 修改 `parseMatchFields()` 接受 `phaseBOMap` 和 `currentSection` 参数（★ 修正 v2 实现缺陷）

```javascript
/**
 * 解析 {{Match}} 模板参数，提取对阵信息。
 * 
 * v3 修正：
 *   - 新增 phaseBOMap 参数：Format 节解析的阶段→BO 映射
 *   - 新增 currentSection 参数：当前 Match 模板所在的 section 名称
 *   - 新增 currentSubsection 参数：当前 Match 模板所在的 subsection 名称（修复 Grand Final 判定）
 *   - 当 bestof 缺失时，使用 currentSection 匹配 phaseBOMap 推断 BO 类型
 *   - 修复 v2 方案中依赖 fields.section 但 section 尚未赋值的 bug
 * 
 * ★ v4 修正（漏洞 1）：Grand Final 位于 ===Grand Final=== 子节下，
 *   currentSection 为 "Playoffs" 而非 "Grand Final"，需通过 currentSubsection 特判。
 */
function parseMatchFields(body, phaseBOMap, currentSection, currentSubsection) {
  // 去掉开头的 'Match|'
  var afterName = body.replace(/^Match\s*\|\s*/, '');
  var parts = splitTopLevel(afterName, '|');
  var fields = {};
  parts.forEach(function (part) {
    part = part.trim();
    var eqIdx = part.indexOf('=');
    if (eqIdx < 0) return;
    var key = part.substring(0, eqIdx).trim().toLowerCase();
    var val = part.substring(eqIdx + 1).trim();
    fields[key] = val;
  });
  
  // 提取队名和比分
  var opp1 = extractTeamOpponent(fields.opponent1 || '');
  var opp2 = extractTeamOpponent(fields.opponent2 || '');
  var team1Name = opp1.name;
  var team2Name = opp2.name;
  if (!team1Name || !team2Name) return null;
  
  // 解析日期
  var startTime = parseLiquipediaDate(fields.date || '');
  if (!startTime) return null;
  
  // ★ v3 修正：bestof 处理 — 优先使用 bestof 字段，缺失时通过 section 推断
  var bo = fields.bestof ? parseInt(fields.bestof, 10) : null;
  
  // ★ v3 修正：bestof 缺失时，使用 currentSection 匹配 phaseBOMap
  if (bo == null || isNaN(bo) || bo < 1) {
    if (phaseBOMap && currentSection) {
      // 精确匹配阶段名
      var mappedBo = phaseBOMap[currentSection];
      // 模糊匹配：currentSection 包含阶段名
      if (!mappedBo) {
        var sectionLower = currentSection.toLowerCase();
        for (var phaseName in phaseBOMap) {
          if (sectionLower.indexOf(phaseName.toLowerCase()) >= 0 ||
              phaseName.toLowerCase().indexOf(sectionLower) >= 0) {
            mappedBo = phaseBOMap[phaseName];
            break;
          }
        }
      }
      // ★ v4 修正（漏洞 1）：Grand Final 子节特判
      // 当 currentSection 为 "Playoffs" 且 currentSubsection 为 "Grand Final" 时，
      // 直接使用 phaseBOMap['Grand Final'] 而非 phaseBOMap['Playoffs']
      // 示例：1win Essence II 的 ===Grand Final=== 子节在 ==Playoffs== 下，
      //   currentSection="Playoffs" → 会匹配到 BO3（错误），需特判修正为 BO5
      if (!mappedBo && currentSubsection && /grand\s+final/i.test(currentSubsection) && phaseBOMap['Grand Final']) {
        mappedBo = phaseBOMap['Grand Final'];
        console.log('[parseMatchFields] Grand Final 子节特判: subsection=' + currentSubsection +
          ' → ' + mappedBo + ' (bestof 缺失)');
      }
      if (mappedBo) {
        var boNum = parseInt(mappedBo.replace('BO', ''), 10);
        if (boNum > 0) {
          bo = boNum;
          console.log('[parseMatchFields] 阶段推断 BO: section=' + currentSection + 
            ' → ' + mappedBo + ' (bestof 缺失)');
        }
      }
    }
  }
  
  // 最终兜底
  bo = (bo != null && !isNaN(bo) && bo >= 1) ? bo : 1;
  var boType = 'BO' + bo;
  
  // finished
  var finished = fields.finished === 'true' || fields.finished === '1';
  // walkover
  var walkover = fields.walkover ? parseInt(fields.walkover, 10) : 0;
  // phase 判定
  var nowSec = Math.floor(Date.now() / 1000);
  var phase;
  if (finished) {
    phase = 'recent';
  } else if (startTime > nowSec) {
    phase = 'upcoming';
  } else if ((nowSec - startTime) < 24 * 3600) {
    phase = 'live';
  } else {
    phase = 'recent';
  }
  
  return {
    team1Name: team1Name,
    team2Name: team2Name,
    score1: opp1.score,
    score2: opp2.score,
    walkover: walkover,
    startTime: startTime,
    boType: boType,
    finished: finished,
    phase: phase
  };
}
```

### 方案 B（必做）：修复 `groupSeries()` 的 BO2 判定逻辑（★ 修正 v2 优先级问题）

**目标**：修复 `series_type` 为 null/undefined 时的 BO2 误判，同时确保 `series_type=1` 明确标记的 BO3 不受影响。

**修改 `sources.js` `groupSeries()` 函数**：

```javascript
// 系列 BO 类型判定（基于胜负场数，比 series_type 更可靠）
// ★ v3 修正：明确的优先级顺序
// 规则：
//   series_type=2 或一方赢3局 → BO5（五局三胜）
//   series_type=1 → BO3（三局两胜，明确标记，优先于场数判定）
//   2场比赛 + 一方2-0 全胜 + series_type!=1 → BO2（双局积分制全胜）
//   2场比赛 + 1-1 平局 → BO2（双局积分制，BO3 不可能平局）
//   一方赢2局 + 场数>2 → BO3（三局两胜，2-1 或 2-0 但场数异常）
//   1场 → BO1
let boType = 'BO1';
const st = first.series_type;
const maxScore = Math.max(scoreA, scoreB);
const minScore = Math.min(scoreA, scoreB);
const totalGames = games.length;

// ★ v3 修正：明确的优先级顺序
if (st === 2 || maxScore >= 3) {
  // series_type=2 明确标记 BO5，或一方赢3局（BO3 不可能出现3胜）
  boType = 'BO5';
} else if (st === 1) {
  // ★ v3：series_type=1 优先于场数判定，确保明确标记的 BO3 不受影响
  // 即使只打了 2 场（2-0 横扫），也判定为 BO3
  boType = 'BO3';
} else if (totalGames === 2 && maxScore === 2) {
  // ★ v3 修正：分散守卫策略
  //   - series_type=0 且 2 场比赛 2-0 → BO2（明确标记为 BO1 系列，实际是 BO2 全胜）
  //   - series_type=null/undefined 且 2 场比赛 2-0 → 保留 BO3（歧义场景，由方案C交叉校正降级）
  //   - series_type=1 已在上方被 BO3 分支拦截，不会走到这里
  if (st === 0) {
    boType = 'BO2';
  } else {
    // st=null/undefined 时保留 BO3，由方案C交叉校正决定是否降级为 BO2
    boType = 'BO3';
  }
} else if (totalGames === 2 && scoreA === 1 && scoreB === 1) {
  // 2 场比赛 + 1-1 平局 → BO2（双局积分制，BO3 不可能平局）
  boType = 'BO2';
} else if (maxScore === 2) {
  // 一方赢2局但场数 != 2（如 2-1 需要 3 场）
  boType = 'BO3';
} else if (maxScore === 1 && totalGames === 1) {
  boType = 'BO1';
} else {
  boType = 'BO1';
}
```

## 10. 附录

### 附录 A：v2 方案逻辑缺陷详细说明

#### A.1 `parseMatchFields()` section 未赋值问题

**v2 方案代码**：
```javascript
function parseMatchFields(body, phaseBOMap) {
  // ...
  var bo = fields.bestof ? parseInt(fields.bestof, 10) : null;
  if (bo == null || isNaN(bo) || bo < 1) {
    if (phaseBOMap && fields.section) {  // ← fields.section 为 undefined
      // 此分支永远不会执行
    }
  }
}
```

**实际执行顺序**：
```javascript
// parseScheduledMatches() 中：
var fields = parseMatchFields(body, phaseBOMap);
// 此时 fields 对象中还没有 section 属性
fields.section = currentSection;  // section 在此处才被赋值
```

**影响**：所有 bestof 缺失的 Match 模板均无法通过 phaseBOMap 推断 BO 类型，全部降级为 BO1 默认值。

#### A.2 Format 节正则容错性不足

**v2 方案正则**：
```javascript
/==\s*Format\s*==\s*\n([\s\S]*?)(?=\n==|$)/
```
- 要求 `==Format==` 后紧跟 `\n`，但实际 wikitext 中可能有多个空行
- 如果内容以 `\n==` 开头（如 `\n==Group Stage==`），则 `(?=\n==|$)` 的零宽断言会匹配到空字符串

**v3 修正正则**：
```javascript
/==\s*Format\s*==\s*([\s\S]*?)(?=\n==[^=]|$)/
```
- 使用 `\s*` 替代 `\n`，兼容任意空白符
- 使用 `\n==\s` 替代 `\n==`，防止零宽断言匹配到空字符串

#### A.3 groupSeries() 优先级问题

**v2 方案代码**：
```javascript
} else if (totalGames === 2 && maxScore === 2) {
  boType = 'BO2';  // 在 st === 1 检查之前
} else if (st === 1) {
  boType = 'BO3';  // 永远不会执行到（因为 totalGames=2, maxScore=2 先匹配）
}
```

**v3 修正**：
```javascript
} else if (st === 1) {
  boType = 'BO3';  // 优先检查明确标记的 BO3
} else if (totalGames === 2 && maxScore === 2) {
  boType = 'BO2';  // 然后检查余下的 BO2 场景
}
```

### 附录 E：与 v2 方案的关键差异（★ v4 补充）
