## ⚠️ 两个必须知道的风险

### 1. 剪切板不勾 → 正式版「复制链接」直接失败

微信官方映射表把 **`wx.setClipboardData` 明确列入「读取你的剪切板」**。官方规则：

> 仅有在指引中声明所处理的用户信息，才可以调用平台提供的对应接口或组件。**若未声明，对应接口或组件将直接禁用。**
> 报错：`A:fail api scope is not declared in the privacy agreement`（errno **112**）

即：不勾「剪切板」，`utils/liveSources.js` 与详情页的「复制链接」在**体验版/正式版会报错**（开发态可能不报，因为开发者工具会预勾）。

### 2. 关于「设备信息」的取舍

- 官方映射表**没有**「设备信息」这一项对应的接口清单 → 说明它属**可自主勾选的补充项**
- 但我们确实调用了 `getDeviceInfo` / `getAppBaseInfo` / `getWindowInfo`（读取 `platform` / `pixelRatio` / `windowHeight`）
- **建议勾上**：漏勾的代价（接口被禁）> 多勾的代价（多一条如实告知）
- **决定性做法**：后台会根据「小程序版本隐私接口调用情况」自动展示**必填项** —— 若「设备信息」被标为必填，就一定要勾

## 附带发现（建议一并处理）

### A. 协议里的「意见反馈」在小程序内并未实现

`privacy.wxml` 第 72、114 行让用户「通过『意见反馈』联系开发者」行使删除权，
但**代码里没有任何反馈功能实现**（全仓仅这两处出现在隐私文案中）。

- 微信官方要求：隐私指引需提供**用户可行使查阅/复制/更正/删除权的联系方式**（后台有独立的联系方式填写项）
- 建议：后台「联系方式」填一个**真实可用的邮箱或微信号**，别只依赖平台内置的反馈入口

### B. 旧接口 `wx.getSystemInfoSync` 已清理

`pages/leagues/leagues.js` 原用已废弃的 `wx.getSystemInfoSync()`（官方说明其「会获取系统权限，可能触发授权弹窗」）。
已改为优先 `wx.getWindowInfo()`，旧接口仅作极旧基础库兜底（2026-09-10 修复）。

## 后台表单其它字段怎么填

除勾选项外，后台模板还有几个字段需要填：

| 字段 | 填什么 | 依据 |
|---|---|---|
| **信息的使用规则** —— 「如开发者使用你的信息超出本指引目的或合理范围，必须在变更目的或范围前，再次以 ___ 方式告知并征得明示同意」 | **弹窗** | 微信官方模板原文即为「**弹窗方式**」；且本项目**未声明收集邮箱/手机号**，承诺邮件/短信通知属无法履约的条款，弹窗是唯一自洽选项 |
| 信息的存储（存储期限） | 建议写**明确期限**，如「实现处理目的所必需的最短期限，最长不超过 30 天（订阅授权状态）」 | 官方要求声明存储期限；本地缓存为 TTL 自动过期，云端 follow_profile 为 30 天 |
| 联系方式 | **真实可用的邮箱或微信号** | 官方要求提供用户行使查阅/复制/更正/删除权的渠道；本项目「意见反馈」功能未实现（见附带发现 A），不能只依赖平台内置入口 |

### ⚠️ 关于「后台文案与页内文案一致性」的正确理解

**2026-09-10 纠正**：此前流传的「两者必须字节一致、审核逐字比对」说法**有误**。

- 后台用的是**平台标准模板**，含固定板块（引导语 / 开发者处理的信息 / 用户权益 /
  开发者对信息的存储 / 信息的使用规则 / 信息对外提供 / 联系方式 / 日期）
- 本仓库的 `privacy.wxml` 是**自定义章节结构** → **结构不同，不可能逐字一致**
- 平台真正校验的是：**声明的信息类型 + 用途 是否与实际隐私接口调用一致**
  （提审时平台自动比对；不一致会拦截，运行时则 `errno 112` 禁用接口）
- `npm run privacy:check` 的用途是防止**本仓库内部**（页内 ↔ 生成的粘贴文案）漂移，
  **不是**用来对齐平台模板
