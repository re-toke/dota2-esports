## 二、逐项 Before / After

### P0-1 · 排名胜率色失效（实际失效点：league-detail，非 leagues）

**根因**：`wr-high/wr-mid/wr-low` 仅定义在 `pages/teams/teams.wxss`（页面级作用域），而
`subpackages/detail/league-detail/league-detail.wxml:239` 的战队胜率列引用了它们，但该页 wxss 只定义了
`.col-num`、无 `wr-*` → 胜率数字无高/中/低颜色区分。最初诊断将其误标为 `leagues.wxml:239`，本次已核对源码修正。

**After（`app.wxss` 全局，约 111 行）**：
```css
/* 胜率颜色分级工具类（全局：teams / league-detail 共用，统一收敛到 kpi Token，禁止本地散落定义） */
.wr-high { color: var(--kpi-primary, #5fd35f); }
.wr-mid  { color: var(--kpi-warning, #f0aa28); }
.wr-low  { color: #8a8f99; }
```
**After（`teams.wxss`）**：删除原 169–171 行本地三定义（去冗余，避免双来源漂移）。

**影响面**：`league-detail` 战绩榜胜率列（绿=高/橙=中/灰=低）恢复语义色；`teams` 页面行为不变（全局覆盖本地，token 一致）。

### P0-2 · 关注卡 Tier 彩条错色

**根因**：`leagues.wxss` 关注卡 `.ff-card.tier-*` 写死字面量，且语义与全局规范冲突——
`tier-s` 写成绿色（应为品牌金）、`tier-a` 写成琥珀（应为紫）。首页 `index.wxss:52-55` 本就用 token，
两处不一致导致「同一赛事在列表是金条（S）、到关注卡却变绿条（S）」。

**After（`leagues.wxss:638-641`）**：
```css
.ff-card.tier-sss::before { background: var(--tier-sss); }
.ff-card.tier-s::before   { background: var(--tier-s); }
.ff-card.tier-a::before   { background: var(--tier-a); }
.ff-card.tier-b::before   { background: var(--tier-b); }
```
**影响面**：与 `index.wxss` 关注流统一——S=金 / A=紫 / B=蓝 / SSS=亮金，全站 Tier 语义一致。

### P0-3 · 资料库品牌栏类名错误

**根因**：`data.wxml` 用了 `brand-info` / `brand-name`，但 `app.wxss` 全局只定义了
`brand-text` / `brand-title` / `brand-sub` / `brand-header` / `brand-logo` → 资料库页品牌标题丢失字号与配色（退化为默认文本）。

**After（`data.wxml:4-5`）**：
```xml
<view class="brand-text">
  <text class="brand-title">DOTA2赛事 · 资料库</text>
```
**影响面**：资料库页品牌栏与赛事页（leagues）品牌栏结构、视觉完全对齐。

## 四、诚实说明：A 版范围之外（建议后续专项，非本次改动）

本次按「低风险治理」原则，**只收编了已确认造成语义错误的散落色值**（tier 彩条、wr-*）。
以下碎片化问题属更大范围重构，未在此次改动，避免引入回归：

- Tailwind 灰阶 `#4b5563/#9ca3af/#d1d5db` 散落多处（follow / league-detail / hero*）；
- 图表/图例硬编码 `#3FB950/#58a6ff` 不在 token 体系；
- 直播色冲突（`live-card` 红 vs 全站「直播=绿 `--status-live`」）；
- `--border` 死 token（全项目未定义，仅靠兜底生效）；
- 未用样式（`.tag/.tag-*` 全套无 wxml 引用）、空态/搜索框双套路等组件冗余。

这些建议作为独立的「设计系统 token 贯彻」专项（可纳入 B 或 C 版落地阶段）。
