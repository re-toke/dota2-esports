## 2. ★ 推荐：**A（微信云开发）+ 顺手做 C**

**为什么 A 是"零成本里唯一能完整恢复"的**：
1. **免域名、免备案、免白名单** —— 走 `wx.cloud.callFunction`，微信内部通道（官方文档明载：云函数调用不计入 request 合法域名）；
2. **云函数在国内** ⇒ 出网用 **DoH(223.5.5.5) 解析真实 IP + IP 直连 + SNI/Host 覆盖** 取 OpenDota
   —— 这套机制我**已在你这台机器/网络实测成功**（HTTP 200 / 32987 bytes）；
3. 它**不碰 Supabase**，所以 `*.supabase.co` 被 SNI 阻断这件事**不再影响它**；
4. 顺带的收益：**curation 等仍可走本地（已在包内 85KB）**，不阻塞。

**代价（一次性、不花钱）**：架构回退 —— 需要
① 重建云开发环境（`config.cloudProxy.envId = cloud1-d2g0wufv8f2ce3871` 还在，代码骨架与 `git log` 可回溯）；
② 恢复"客户端 → 云函数"调用链（`_cloudFetchViaCloud` 当时被移除）⇒ **中等工作量，有底**。

**落前必须先验证 2 件事**（都不花钱，我可以帮你做）：

## 3. 备选 B（零后端）的可行边界（诚实说）

**能直连（均实测可达）**：`dota.haglund.dev` ✓（赛程）、`liquipedia.net` ✓（赛事元数据/分级）、`api.steampowered.com` ✓（Valve 官方，比分/结果候选）
**只能靠烘焙（随发版）**：战队/队员详情、英雄/物品（这些**没有可达替代源**）⇒ **CI 生成快照 → 随发版带入**（低频数据，可接受）
**完全拿不到**：OpenDota 的 `tier` 分级、全量赛事列表、`/explorer` 时间窗 ⇒ 赛事页规模会明显缩水 ⚠️

⇒ B 适合"**能接受赛事列表以策展为准、详情页偏静态**"的取舍。

## 4. 备选 C（最小改动，先救命）

零成本、改动小，**不恢复实时但能立刻改善观感**：
1. **失败原因上屏**：把"更新失败"改成可读原因（网络不可达 / 云端不可达 / 超时）⇒ 用户知道不是 App 坏了；
2. **快照随发版更新**：CI（境外）每天已在刷新快照 ✓ ⇒ **只要发一次版**，包内快照就是新的（未来靠"定期发版"保新鲜）；
3. 「数据健康」卡显示**云端通道不可达**（现在它对通道全死是无感的）。

## 5. 建议的选择顺序

```
先做 C（最小成本、立刻改善）——1 天内可完成
   ↓
再验 A 的两个前提（都不花钱）——若都通过 ⇒ 走 A（零成本完整恢复）
   ↓
若 A 的前提不通过 ⇒ 退到 B（零成本、但数据覆盖缩水）
```

**要你定的只有一件事**：**先做 C 吗？**（以及你愿意花"一次性工作量"换"完整恢复"吗 —— A 需要动架构回退，但**不花钱**。）
