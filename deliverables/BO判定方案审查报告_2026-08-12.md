## 一、实现现状概览（代码链路）

```
Liquipedia wikitext
  → parseScheduledMatches() 逐行扫描 {{Match}} 模板，维护 currentSection/currentSubsection
  → parseMatchFields(body) 单参数：提取 bestof/队名/比分/matchIds/finished
     · bestof 缺失 → boType='BO1' + boDeclared=false（占位，交引擎重判）
     · 注：v3/v4 方案的 parseMatchFields(body, phaseBOMap, section, subsection) 多参数版未落地
  → parseBoFormat(wikitext) 解析 ==Format== 段 → { group, playoff, grandFinal, default }（S2 信号）

OpenDota /leagues/{id}/matches
  → groupSeries() 按 series_id 分组，旧比分反推 boType（被 applyBo 覆盖）
     · 透传 seriesType（series_type）给引擎
     · ⚠️ 同时计算 isDraw/scoreACls/teamACls 样式（基于旧 boType，applyBo 不重算）

league-detail.buildSeriesFromSources：
  1. absorbSettledGames(allSeries, liqSeries, resolver) — S0 matchIds 硬关联 + S1 队名+时间窗(仅 live,4h)
  2. buildBoContext(allSeries, league) — 预算 dailyDraws/stages/uniBo/stageKey(LP section 锚点优先 + OD 时间簇)
  3. allSeries.map(applyBo) — resolveBoType S1→S2→S3→S4→S5→S6 + consistent 约束 + finalize 抬升
  4. liveProgressOf — 依赖最终 boType
```

**信号优先级**：S1 每场声明 bestof → S2 赛制文本(parseBoFormat/uniBo) → S3 series_type(0/1/2/3) → S4 同日自证(UTC 日 1:1) → S5 局数比分约束(仅 RECENT) → S6 阶段默认(playoff→BO3 先验/众数)

## 二、不足之处

### P0-1 · groupSeries isDraw 样式与 applyBo boType 不一致（显示 bug）

**位置**：[sources.js#L942](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/sources.js#L942) + [sources.js#L1250](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/sources.js#L1250)

**问题**：`groupSeries` 在第 942 行基于**旧比分反推 boType** 计算 `isDraw`/`scoreACls`/`teamACls` 等样式字段；随后 `applyBo` 覆盖 `boType` 但**不重算这些样式字段**。

```javascript
// groupSeries（L942）— 基于旧 boType
const isDraw = boType === 'BO2' && scoreA === scoreB;
const scoreACls = isDraw ? 'draw' : (scoreA > scoreB ? 'win' : 'lose');
// ... teamACls / teamBLogoCls 同理

// applyBo（L1250）— 只覆盖 boType/boLabel/boTagCls/isMulti，不碰 isDraw
function applyBo(series, ctx) {
  const bo = resolveBoType(series, ctx);
  series.boType = bo;
  series.boLabel = BO_LABEL[bo] || '单局制';
  series.boTagCls = bo === 'BO2' ? 'bo-bo2' : (bo === 'BO5' ? 'bo-bo5' : '');
  series.isMulti = bo !== 'BO1';
  return series;   // ⚠️ isDraw/scoreACls/teamACls 残留旧值
}
```

**触发场景**：OpenDota LIVE 卡 BO3 进行中 1:1（第 2 局打完、第 3 局 pending）：
- `groupSeries`：`maxScore=1, totalGames=2, 1==1` → 旧 `boType='BO2'` → `isDraw=true`
- `resolveBoType`：S3 `st=1` → `consistent('BO3')` 通过（`isFinished=false`，不校验终局）→ 返回 `BO3`
- `applyBo`：`boType='BO3'`，但 `isDraw` 残留 `true`
- **显示**：BO3 进行中 1:1 被渲染为「平局橙色样式」（draw），而 BO3 1:1 是进行中状态，非终局平局

**影响**：OpenDota 来源的 LIVE 卡（未被 LP 吸收的）在 BO3/BO5 进行中 1:1/2:2 时误显示平局样式。LP 来源卡因 `liqIsDraw` 限定 `phase==='recent'`（[league-detail.js#L823](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/subpackages/detail/league-detail/league-detail.js#L823)）不受影响。

**修复建议**：`applyBo` 内根据最终 `boType` 重算 `isDraw` 及衍生样式：
```javascript
function applyBo(series, ctx) {
  const bo = resolveBoType(series, ctx);
  series.boType = bo;
  series.boLabel = BO_LABEL[bo] || '单局制';
  series.boTagCls = bo === 'BO2' ? 'bo-bo2' : (bo === 'BO5' ? 'bo-bo5' : '');
  series.isMulti = bo !== 'BO1';
  // ★ 重算 isDraw：仅 BO2 + 已结算 + 比分相等 才为平局（BO3/BO5 进行中 1:1 不是平局）
  const isFinished = series.phase === 'recent';
  series.isDraw = (bo === 'BO2' && isFinished && (series.scoreA === series.scoreB));
  // 衍生样式按需重算（若 wxml 依赖 isDraw 而非 scoreACls，则只需 isDraw）
  return series;
}
```

### P0-2 · TI 2026 Group Stage UPCOMING 误判 BO1（用户实测反馈）

**位置**：[liquipedia-parse.js#L585-L586](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/liquipedia-parse.js#L585)（parseMatchFields bestof 兜底）+ [liquipedia-parse.js#L867](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/liquipedia-parse.js#L867)（parseBoFormat）+ [sources.js#L1245](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/sources.js#L1245)（S6 兜底）

**用户反馈**：TI 2026 赛事详情页-对阵-UPCOMING 中所有比赛显示 BO1，实际 Group Stage 是 BO3。

**根因分析**（通过抓取 TI 2026 Group Stage 真实 wikitext 验证）：

TI 2026 的 `scheduledMatchesSlug` = `The_International/2026/Group_Stage`（curation 配置）。该子页面的 wikitext **完全不含 BO 赛制信号**：

| 信号源 | wikitext 实测 | 引擎处理结果 |
|--------|---------------|-------------|
| `==Format==` 段 | **不存在**（页面无 Format 二级/三级标题） | `parseBoFormat` 返回 `{ group:null, playoff:null, grandFinal:null, default:null }` |
| `{{Match|bestof=N}}` | **44 个 Match 模板全部无 bestof 字段** | `parseMatchFields` 兜底 `bo=1` → `boType='BO1'`，`boDeclared=false` |
| infobox format | **无 infobox** | `metaFormatBo = null` |
| 文本 "Bo3"/"best of 3" | **整个页面零匹配** | 无任何 BO 文本信号 |
| map 槽结构 | 每场 **3 个 map 槽**（map1/map2/map3，暗示 BO3） | ⚠️ **信号被丢弃**（见下文） |

**resolveBoType 信号链逐级失效**（TI 2026 UPCOMING 卡）：

```
S1 每场声明（declaredBo）  → null（bestof 缺失，boDeclared=false）       ✗
S2 赛制文本（boFormat）    → null（parseBoFormat 全 null，云函数/本地均同） ✗
S3 series_type             → null（LP 来源无 series_type）               ✗
S4 同日自证（dailyDraws）  → false（UPCOMING 未结算，无 1:1 平局样本）    ✗
S5 局数比分约束            → 跳过（phase !== 'recent'）                    ✗
S6 阶段默认                → stageKey='group'（非 playoff/grandFinal）
                             → 返回 c.defaultBo
                             → 赛事未开打无 RECENT 样本 → defaultBo='BO1'  → 显示 BO1 ✗
```

**核心问题**：TI 2026 wikitext 采用「瑞士轮」格式（`{{SwissStandings}}` + `{{Matchlist}}` + `{{Match}}`），**赛制信息不在页面内**（Liquipedia 编者依赖页面模板默认值或赛事主页声明）。所有 6 级信号全部失效 → 兜底 BO1。

**被丢弃的关键信号 — map 槽数**：

`parseMatchFields`（[liquipedia-parse.js#L608-L632](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/liquipedia-parse.js#L608)）已扫描 `map1`-`map5` 字段并计算 `_mapCount`，但仅用于 `finished` 判定，**未返回到 series 对象**：

```javascript
// parseMatchFields 内部（L608-L632）
var _mapCount = 0;
for (var _mi = 0; _mi < _mapKeys.length; _mi++) {
  var _mv = fields[_mapKeys[_mi]] || '';
  if (!_mv) continue;
  _mapCount++;                    // ← 计算了 map 槽数（TI 2026 = 3）
  // ... 仅用于 finished 判定
}
// return { ... }                  // ⚠️ _mapCount 未返回！
```

TI 2026 每场 3 个 map 槽 = BO3 的结构铁证（BO1 只有 1 个槽，BO2 有 2 个，BO3 有 3 个，BO5 有 5 个），但这个信号被丢弃了。

**影响范围**：所有 Liquipedia 页面不含 `==Format==` 段且 `{{Match}}` 模板无 `bestof` 字段的赛事。实测 TI 2026（瑞士轮格式）受影响；其他采用传统 `==Format==` 段的赛事（如 1win Essence II）不受影响。

**修复方案（推荐方案 A：map 槽数信号）**：

将 `_mapCount` 作为新信号 `mapSlots` 返回到 series 对象，在 `resolveBoType` 中作为 S2b 信号（map 槽结构推断）：

```javascript
// 1. parseMatchFields 返回 mapSlots（liquipedia-parse.js）
return {
  team1Name: team1Name,
  // ... 原有字段 ...
  mapSlots: _mapCount || 0   // ★ 新增：map 槽数（BO 结构铁证）
};

// 2. league-detail.js 透传到 series 对象（LP 卡构造处，约 L828）
return {
  // ... 原有字段 ...
  mapSlots: m.mapSlots || 0  // ★ 透传
};

// 3. resolveBoType 新增 S2b 信号（sources.js，S2 之后、S3 之前）
//    map 槽 → BO 映射：1→BO1 / 2→BO2（双局积分）/ 3→BO3 / 5→BO5
//    注意：4 槽是 BO3 的「预留第 4 局」（罕见），保守判 BO3
if (!fmtBo && series.mapSlots) {
  const slotBo = { 1: 'BO1', 2: 'BO2', 3: 'BO3', 5: 'BO5' }[series.mapSlots];
  if (slotBo && consistent(slotBo)) return finalize(slotBo);
}
```

**修复方案（备选方案 B：curation boFormat 补充）**：

在 curation 配置中为 TI 2026 显式声明 boFormat：

```javascript
// utils/curation.js TI 2026 条目
{ canonical: 'The International 2026', ...
  boFormat: { group: 'BO3', playoff: 'BO3', grandFinal: 'BO5' },  // ★ 新增
  // ...
}
```

**方案对比**：

| | 方案 A（map 槽信号） | 方案 B（curation boFormat） |
|---|---|---|
| 通用性 | ✅ 所有赛事自动生效 | ❌ 每个赛事手工配 |
| 维护成本 | 低（零配置） | 中（新赛事需补） |
| 可靠性 | 高（map 槽 = BO 结构铁证） | 高（人工策展） |
| 覆盖面 | 所有 LP 有 Match 模板的赛事 | 仅 curation 覆盖的赛事 |
| 落地速度 | 需改 3 文件 + 测试 | 需改 1 文件 |

**建议**：**方案 A + B 同时落地**。方案 A 是通用解（根治同类问题），方案 B 是即时补丁（TI 2026 开赛在即，curation 可立即生效无需等代码发布）。

### P1-1 · LIVE 零信号先验回退到 BO1

**位置**：[sources.js#L1243](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/sources.js#L1243)（S6 兜底）

**问题**：LIVE 卡（LP 来源）常见零信号组合：
- `declaredBo=null`（bestof 缺失）→ S1 失效
- `boFormat=null`（云函数未部署）→ S2 失效
- `seriesType=null`（LP 无 series_type）→ S3 全跳过
- `sameDayDraw=false`（LIVE 未结算无 1:1 自证）→ S4 失效
- `phase='live'` → S5 跳过（仅 RECENT）
- S6：`stageKey` 非 playoff/grandFinal → 返回 `c.defaultBo`

`defaultBo` 来自 RECENT 模式众数；赛事初期无 RECENT 样本 → `BO1`。**结果：LIVE 零信号 → BO1 误判**（实际可能 BO3）。

**影响**：云函数未部署 + 赛事初期（无已结算局）的 LIVE 卡显示「单局制」，与实际赛制不符。

**修复建议**：S6 兜底前增加 LIVE 阶段先验 —— LIVE 卡无任何信号时，按联赛 tier 或历史同赛事 RECENT 样本推断；最保守可对 S-Tier/TI 赛事 LIVE 默认 BO3（淘汰赛先验已覆盖 playoff，但小组赛 group 阶段仍会落到 defaultBo）。

### P1-2 · S4 同日自证 UTC 日历日粒度失效（北美赛事）

**位置**：[sources.js#L1136](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/sources.js#L1136)（`dailyDraws` key = `Math.floor(lastTime / 86400)`）

**问题**：`dailyDraws` 用 UTC 整日作为 key。北美赛事（UTC-5~-8）当地晚间 20:00 开赛的 BO2 两局可能跨 UTC 00:00（当地 19:00 / 20:00 = UTC 次日 00:00 / 01:00），导致同一场 BO2 的两局分属不同 UTC 日 → `dailyDraws` 不标记 → S4 自证失效。

**影响**：北美小组赛 BO2 的 1:1 平局若跨 UTC 日，S4 无法识别 → 退化为 S5（2:0 保守 BO3）或 S6。文档已记录此边界（Doc2 R4），接受「保守只漏判不误判」。

**修复建议**（可选）：将 UTC 日改为 ±12h 滑动窗口——`dailyDraws` 检查 `series.lastTime ± 12h` 内是否存在 1:1 平局，覆盖跨日场景。
