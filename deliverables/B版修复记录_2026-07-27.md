# B 版密度版 · 修复记录（2026-07-27）

> UI Designer 交付 — 基于《UI优化设计方案_多版本.md》中 B 版（密度版 / 数据党）的实施。

## 设计思路

B 版定位"核心玩家 / 数据分析用户"，核心目标是**释放被筛选控件占满的首屏**，并**提升列表信息密度**。

改造前：赛事页首屏有 **4 行筛选控件纵向堆叠**（状态 / 等级 / 视图+排序 / 战队），加上焦点卡，列表可视区仅约 40%。
改造后：
- 最高频的**状态切换常驻单行**（全部 / 进行中 / 即将 / 已结束），可横向滚动；
- 等级 / 排序 / 视图 / 战队统一收进 **「筛选▾(N)」底部抽屉**，N = 生效的非默认筛选数；
- 列表**来源并入一行**、压缩卡片内边距与间距，密度显著提升。

## 改动清单

### 1. 赛事页筛选收拢（B-1）— `pages/leagues/`
- **leagues.wxml**：删除原 `grade-bar` / `view-mode-bar` / `team-filter-row` 三行常驻；
  顶部工具条改为 `[状态 chips 横向滚动] + [筛选▾(N) 按钮]`；新增底部筛选抽屉（等级 / 排序 / 视图 / 战队 + 重置 / 完成）。
- **leagues.js**：`data` 新增 `filterPanel` / `activeFilterCount`；`applyAndSlice` 开头调用 `syncFilterBadge`；
  新增 `openFilterPanel` / `closeFilterPanel` / `resetFilters` / `syncFilterBadge`。
- **leagues.wxss**：覆盖全局 `.filter-bar` 布局（scroll-view + filter-toggle 横向排列），新增筛选抽屉 `fp-*`、`filter-toggle` / `filter-badge` 样式，复用既有 `.gc` 等级芯片视觉。

### 2. 列表表格化（B-2）— `pages/leagues/`
- **leagues.wxml**：主列表 `league-main` 删除独立 `league-source-row`，来源以 `.src-inline` 并入 `league-sub` 一行。
- **leagues.wxss**：`league-item` padding `24→18rpx`、margin `16→12rpx`；`league-sub` / `league-countdown` margin-top `8→6rpx`；新增 `.src-inline` 及 `.src-*` 来源配色（社区分级=金 / Liquipedia=蓝灰 / STRATZ=绿 / OpenDota=灰）。
- **密度估算**：单卡高度约 `188rpx → 150rpx`（约 +20%）；叠加首屏筛选 4 行→1 行，列表可视区由 **~40% 升至 ~65%**。

### 3. 搜索命令面板（B-3）— `pages/search/`
- **search.wxml**：初始态新增「最近搜索 / 热门搜索」快捷标签区（命令面板入口感）。
- **search.js**：`data` 新增 `hotTerms` / `history`；`onLoad` 读取历史；新增 `onQuickTap` / `runKeyword` / `pushHistory` / `clearHistory`；`doSearch` 记录历史（本地存储，最多 8 条去重）。
- **search.wxss**：新增 `.search-quick` / `.qk-*` 样式（胶囊标签，点击即搜）。

- 旧筛选类 `grade-bar` / `view-mode-bar` / `team-filter-row` / `league-source-row` 已从 wxml 移除，**零残留**；

## 设计取舍（说明）

- **状态 chips 常驻而非收进抽屉**：状态是最高频浏览维度（进行中 / 即将 / 已结束），常驻切换成本最低，符合"密度版"的实用导向。
- **列表 / 周轴视图切换收进抽屉**：默认列表视图，绝大多数用户不切，降低首屏噪音。
- **未做"全局命令面板浮层"（输入即指令）**：当前 search 已具备"输入即分组"，B-3 仅补快捷入口，作为轻量增强；真正的指令面板浮层列为后续增强项。

## 范围外（未改）
