## 3. 数据结构

迁移后云数据库 collection 结构：

### 3.1 `curation_events` collection
| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 规范名归一化（`consensus.normName(canonical)`），主键 |
| `canonical` | string | 规范名（如 `The International 2026`） |
| `aliases` | string[] | 别名数组（小写无分隔形式） |
| `tier` | object | `{ grade, rank, label }` |
| `year` | number | 年份 |
| `start` / `end` | number | Unix 秒（UTC） |
| `liquipediaSlug` | string | Liquipedia 页面 slug |
| 其他扩展字段 | any | prizePool / organizer / region / format / participants / status / valve / topThirdParty |
| `updatedAt` | number | 写入时间戳（ms） |

### 3.2 `curation_teams` collection
| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | team_id 字符串形式（云数据库 _id 必须是字符串） |
| `name` / `tag` / `country` | string | 战队基本信息 |
| `tier` | object | `{ grade, rank, label }` |
| `aliases` | string[] | 别名数组 |
| `updatedAt` | number | 写入时间戳（ms） |

### 3.3 `curation_meta` collection
| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 固定值 `ti_contestant_ids` |
| `ids` | number[] | 历届 TI 参赛队 ID 集合 |
| `count` | number | ids 长度 |
| `version` | string | 8 位数据指纹（MD5 前 8 位），用于客户端增量更新 |
| `updatedAt` | number | 写入时间戳（ms） |

**version 计算逻辑**（见 [migrate-curation-to-db.js#L181-L192](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/scripts/migrate-curation-to-db.js#L181-L192)）：
```js
MD5({
  eventsCount, teamsCount, tiIdsCount,
  eventsCanonical: events.map(e => e.canonical).sort().join(','),
  teamsIds: Object.keys(teams).sort().join(',')
}).slice(0, 8)
```

### 7.1 客户端回退（无需操作）
[remoteCuration.js#L34-L48](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/remoteCuration.js#L34-L48) 的 `ensure()` 函数内置本地兜底：

- 云数据库读取失败 → 云函数返回 `error`，客户端 `console.warn` 后回退本地
- 即：**即使云端 curation 完全不可用，小程序功能不受影响**

### 7.2 完全回滚（禁用云端 curation）
如需完全禁用云端 curation，回到纯本地模式：

**方法1（推荐，临时禁用）**：清空本地 version 缓存，强制下次重新拉取
```js
// 微信开发者工具 Console 执行
wx.removeStorageSync('remote_curation_v2')
wx.removeStorageSync('remote_curation_version')
```

**方法2（永久禁用）**：注释 [app.js#L37](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/app.js#L37) 的 `remoteCuration.load()` 调用，客户端将始终使用本地 curation.js

**方法3（云端禁用）**：在云开发控制台删除 `curation_events` / `curation_teams` / `curation_meta` 三个 collection，云函数 `getCuration` 会返回错误，客户端自动回退本地

### 7.3 数据回滚（恢复旧版本 curation）
如云端 curation 数据被误改，需恢复到某个版本：
1. 找到对应的 [utils/curation.js](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/curation.js) 历史版本（git checkout）

## 8. 增量更新机制说明

### 8.1 工作流程
```
客户端启动
  ↓
remoteCuration.load()
  ↓
读取本地 clientVersion（cache.getStale VERSION_KEY）
  ↓
调云函数 getCuration(clientVersion)
  ↓
云函数对比云端 version
  ├─ 一致 → 返回 { unchanged: true }，客户端仅刷新缓存时间戳
  └─ 不一致 → 返回 { data: {...}, version }，客户端构建 effective 集合并缓存
```

### 8.2 version 一致时的收益
- 零数据传输（不传 events/teams 数组）
- 客户端不重建 lookups，节省 CPU
- 云函数命中 L1 内存缓存，不读云数据库

### 8.3 version 变更触发
云端 version 由 `computeVersion()` 计算（见 [migrate-curation-to-db.js#L181-L192](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/scripts/migrate-curation-to-db.js#L181-L192)），以下任一变更会改变 version：
- events 数量变化（新增/删除赛事）
- teams 数量变化（新增/删除战队）
- tiIds 数量变化
- events 的 canonical 集合变化（重命名赛事）
- teams 的 ID 集合变化

> ⚠️ **注意**：修改单个赛事的 `start` / `end` / `prizePool` 等字段**不会**改变 version（因为这些字段不参与指纹计算）。  
> 这是有意设计：避免高频的赛期微调导致全量数据重传。  
> 副作用：客户端拿到的 curation 数据中，赛期等字段在 version 不变时不会更新。  
> 解决：阶段2 管理后台会扩展 version 计算逻辑，纳入所有业务字段。

## 9. 缓存层级

```
客户端
  ↓ cache.getStale(CACHE_KEY)  ← 本地 Storage（TTL = remoteCuration.ttlSec = 6h）
  ↓
云函数 handleGetCuration
  ↓ _curationL1Cache  ← 云函数实例内存（TTL = 10min）
  ↓
云数据库 loadCurationFromDB
  ↓ curation_events / curation_teams / curation_meta collection
```

**降级链路**：
1. 客户端缓存新鲜 → 直接用缓存，不调云函数
2. 客户端缓存过期 → 调云函数，云函数命中 L1 → 返回 L1 数据
3. L1 过期 → 云函数读云数据库 → 回填 L1 → 返回
4. 云数据库读取失败 → 云函数返回 L1 过期缓存（`source: 'cache_fallback'`）
5. L1 也无 → 云函数返回 error → 客户端回退本地 curation.js

## 11. 常见问题

### Q1：迁移脚本报 `❌ 缺少 wx-server-sdk 依赖`
**A**：在 `cloudfunctions/aggregation` 目录执行 `npm install` 后重试。脚本依赖 `wx-server-sdk` 连接云数据库。

### Q2：迁移脚本报 `❌ 未配置 cloudProxy.envId`
**A**：检查 [utils/config.js#L162](file:///d:/WorkBuddy项目文档/2026-07-19-15-21-29/dota2-esports/utils/config.js#L162)，确保 `cloudProxy.envId` 已填写云开发环境 ID。

### Q3：客户端日志显示 `[remoteCuration] 云函数返回错误`
**A**：排查顺序：
1. 云函数是否已部署（含 `getCuration` handler）
2. 云数据库三个 collection 是否有数据（迁移是否执行）
3. 云函数日志（云开发控制台 → 云函数 → aggregation → 日志）

### Q4：客户端日志显示 `[remoteCuration] 云函数调用失败`
**A**：排查顺序：
1. `config.cloudProxy.enabled` 是否为 `true`
2. `config.cloudProxy.envId` 是否正确
3. 熔断器是否触发（连续失败 3 次）→ Console 执行 `wx.removeStorageSync('dota2_cloud_cb')` 清除熔断状态
4. 业务不受影响（自动回退本地 curation.js）

### Q5：迁移后客户端数据没更新
**A**：检查 clientVersion 增量更新逻辑：
1. Console 查看 `wx.getStorage('remote_curation_version')` 的值
2. 云函数返回的 version 是否与本地一致（一致则 `unchanged`，不重传数据）
3. 如需强制刷新：Console 执行 `wx.removeStorageSync('remote_curation_v2')` 和 `wx.removeStorageSync('remote_curation_version')` 后重启

### Q6：修改了 curation.js 但云端没更新
**A**：阶段1 **不会自动同步**。需要手动执行 `npm run migrate:curation` 重新迁移。自动同步在阶段3 实现。
