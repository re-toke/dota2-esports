## 四、🔴🔴 最重要发现：`.limit(500)` 硬上限 —— 两个真问题

### 问题 A：客户端**最多只能拿到 500 条**远程 curation

`cloudfunctions/aggregation/index.js` 的 `loadCurationFromDB()`：

```js
db.collection('curation_events').limit(500).get(),   // ← 单次上限 500
db.collection('curation_teams').limit(500).get(),
```

**集合里有 2,414 条，客户端最多拿到 500 条**，且**没有 orderBy**（无序取样）。

→ 修正我此前的说法：「赛事列表 97% 来自云开发」应改为
「**客户端最多拿到 500 条远程 curation**（仍远多于打包的 73 条），但**取哪 500 条不确定**」。

### 问题 B：🔴 **新赛事自动发现很可能已经失效**

`cron-discover-tournaments/index.js` L350：

```js
const res = await db.collection(CURATION_EVENTS_COLL).limit(500).get();  // ← 只读前 500
```

它用这 500 条构造 `existing` 集合，再和 Liquipedia 全量对比找「未收录」的。

**但集合里实际有 2,414 条** → 剩下 **1,914 条被判为「未收录」**（假新赛事）。

接着 L371-377：

```js
const MAX_INSERT = 100;                      // 单次最多写 100 条
const itemsToInsert = newItems.slice(0, 100);  // ← 只取前 100
console.log('[cron-discover] 新赛事 ' + newItems.length + ' 条超过上限...');
```

→ `newItems` ≈ 1,914 条（几乎全是已存在的），**真正的全新赛事排在它们后面**，
每次只插前 100 条（且都是已存在的，upsert 无害但白跑）。

**结论：`dailyDiscover` 现在很可能是「每天照跑、但实际收不进新赛事」。**

### 👉 请你在控制台验证（1 分钟）

看 `admin-logs` 集合里最近几条 `action='cron_discover'` 的记录：

| 观察 | 说明 |
|---|---|
| `newCount` 长期是 **~1900 左右** | ✅ 证实上述推断（假新赛事淹没了真新） |

| 没有 `cron_discover_alert` | 佐证「长期没发现真正的新赛事」 |

**如果证实**：这是**独立于迁移的真实产品缺陷** —— 赛事自动收录已经停摆，
而迁移到 Supabase（无 500 上限）会**顺带修好它**。

## 五、字段映射推导（待样本验证）

### `curation_events` → Supabase `curation_events(league_id, data jsonb)`

`loadCurationFromDB` 的写入方逻辑：

```js
const e = Object.assign({}, doc);
delete e._id;          // 云数据库元字段
delete e.updatedAt;    // 云数据库时间戳
return e;              // ← 其余业务字段「原样透传」
```

→ 即**云开发 doc 的业务字段 = 客户端期望的字段**，无需转换。
→ 映射方式：`data = 去掉 _id/updatedAt 后的整个 doc`；
   `league_id` 待确认（**云开发 doc 的 `_id` 是 league_id 还是规范名？**）

### `curation_teams` → Supabase `curation_teams(team_id, data jsonb)`

```js
const tid = doc._id;
teams[Number(tid)] = t;   // _id 即 team_id（数字）
```
→ 明确：`_id` 是 team_id → `team_id = Number(_id)`, `data = 去掉 _id/updatedAt 的 doc` ✅

### `curation_meta` → Supabase `curation_meta(key, ...)`

```js
db.collection('curation_meta').doc('ti_contestant_ids').get()
const tiContestantIds = meta.ids || [];
```
→ 需要 Supabase `curation_meta` **存 `{key:'ti_contestant_ids', ids:[...]}`**（schema 待核对）
