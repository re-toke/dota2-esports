## 一、先更正一处关键判断（影响整个计划的制定）

在制定计划前的可行性验证中，发现**复核报告 §5.3 的一个结论是错的**，必须先更正，否则计划会走偏。

### 错误内容
复核报告称：
> 「修复成本：`package.json:9` 的 `test:all` 末尾追加一行即可为首页模块建立回归保护」

### 实际情况
读了 `scripts/test/test-home-series.js` 的实现：

```js
// scripts/test/test-home-series.js:14
const sources = require('../../utils/sources.js');        // ← 只加载 sources.js

// :22-27
// —— 首页 _applyMatchSources 三源合并 → series 化（与 index.js L458-464 同链路）——
function resolveAll(matches) {
  const series = sources.groupSeries(matches);
  const ctx = sources.buildBoContext(series, null);
  return series.map(function (s) { return sources.applyBo(s, ctx); });
}
```

**该测试测的是 `utils/sources.js` 的纯函数**（`groupSeries` / `buildBoContext` / `applyBo`），
index.js 的链路是**手工复刻**（注释自称"同链路"），而非 import。

**因此它无法捕获 P0-1** —— P0-1 位于 `pages/index/index.js` 的 `_renderMatchFlow` / `passGrade`，
而**全项目没有任何测试加载 index.js**。

### 更正后的三层事实
| 层 | 事实 | 状态 |
|---|------|------|
| ① `test-home-series.js` 未接入 `test:all` / pre-commit | **属实**（接线缺口真实存在） | 应修，但它保护的是 sources 层 |
| ② 它能否拦住 P0-1 | **不能**（不加载 index.js） | 复核报告此处判断错误 |
| ③ 原审计报告「页面层零测试覆盖」 | **是对的**（index.js 确实零覆盖） | 复核时的"纠正"反而错了 |

### 对计划的含义
> **P0-1 的防线需要"新增"，不是"接通"。** 仅改 `package.json` 不能防止此类问题复发。


| 对比 | 方案 A | 方案 B |
|---|---|---|
| 改动量 | 3 处各加 1 行 | 1 处改 2 行 |
| 语义清晰度 | **高**（读 `c.tier.grade` 直白） | 中（依赖 class 命名约定 `tier-`） |

| 副作用 | 无 | 若未来 `tierClass` 命名变化会静默失效 |

→ **推荐方案 A**。但**无论选哪个，都必须配批次 0 的契约测试**。
