## 4. 解决方案（**待拍板，本次不落地**）

### R1 —— 立刻可做、零成本、用来**定性**（今天就能判定）
1. **换网络复测**：WiFi ↔ 手机流量（4G/5G）各试一次；
2. **关掉手机上所有 VPN/代理/加速类 App** 再测（`ERR_CERT_AUTHORITY_INVALID` 常由它们注入证书导致）；
3. **校准手机系统时间**（时间偏差会造成证书校验失败）；
4. 结论判定：
   - **任一网络下恢复** ⇒ 属"该网络环境"问题；
   - **所有网络都不恢复** ⇒ **域名级不可达** ⇒ 走 R2。

### R2 —— **架构级，建议必做**（这是本次最根本的一条）
> **`*.supabase.co` 在国内网络不可靠**（真机重置 + 沙箱同样重置，两处独立复现）。
> 而本小程序的用户**全在国内** ⇒ **把后端域名换成一个国内可达的自有域名**是根治手段。

做法（按代价排序）：
| 方案 | 做法 | 评价 |
|---|---|---|
| **R2-a（推荐）** | 用**国内服务器/云函数做反向代理**（自定义域名 + HTTPS，指向 Supabase EF/PostgREST），客户端 `config.supabase.url` 改为该域名 | 根治；需备案域名（你已有域名/备案经验） |
| R2-b | 只把**数据面**迁到国内可得源（如自建 OpenDota 代理 + 本库表） | 工作量大 |
| R2-c | 仅换 Supabase **自定义域**（Custom Domain） | ⚠️ 仍是 Supabase/Cloudflare 边缘，国内仍可能被重置，**不保险** |

### R3 —— 代码侧（**需发新版本**，与 R2 并行做）
1. **修 `anonKey`**（用真 key 替换 `config.js:226`）+ **加形状守卫**（非 `eyJ`/长度<100 ⇒ 视为未配置并上屏提示）；
2. **失败原因上屏**：现在失败只在 console（`ERR_CONNECTION_RESET` 用户看不到），页面只说"更新失败"；
   建议把「网络不可达 / 证书错误 / 云端 401」分类显示 ⇒ 下次不用再靠真机调试猜；
3. **直连兜底加厚**：客户端对 `/leagues` 直连响应做本地裁剪（或单独放宽超时）⇒ 不再单点依赖 EF；
4. **熔断可观测化**：熔断后「数据健康」卡显示"云端通道已熔断（本会话）"。

### R4 —— 重复卡片（独立小修，需发版）
- 合并键**补"双方都有 team id 时的 id 键"**（`_teamToken` 目前 **队名非空时不用 id**）；
- 把 `1w Team`/`1win` 固化为 `homeDedupe` 的**回归用例**；**禁用模糊匹配**（错误合并比重复更危险）。

公共键 = []   ⇒ 不合并 ⇒ 两张卡

## 6. 结论（v3）

1. **根因是网络层**：`*.supabase.co` 在国内网络**被重置**（真机 + 沙箱双复现），直连 `api.opendota.com` **证书不受信**
   ⇒ 客户端**无法取数** ⇒ 只剩内置快照。**这与白名单、客户端密钥、超时、代码回归都无关**（均已排除）。
2. **必须做架构级改动（R2）**：把后端域名换成**国内可达的自有域名** —— 否则即使升带宽、修代码，国内用户依然取不到数据。
3. **`anonKey` 仍需修（R3）**：它是真缺陷，会在连通性恢复后立刻暴露为 401。
4. **问题③ 已有复现与修法（R4）**。
