## 1. 问题描述

在赛事详情页的「对阵」模块中，LIVE/UPCOMING/RECENT 三段对局的 BO 赛制判定存在错误。以 **1win Essence II** 为例：

- 截至 2026-08-03 00:30（北京时间），该赛事所有比赛均为小组赛阶段
- 小组赛全部采用 **BO2（双局积分制）** 赛制（Format 说明明确标注："All matches are {{Abbr/Bo2}}"）
- 但赛事详情页中：
  - **RECENT 段**（OpenDota 数据）：比赛显示为 **BO3**（误判）
  - **UPCOMING/LIVE 段**（Liquipedia 数据）：比赛显示为 **BO1**（误判）

## 2. 现有方案（2026-08-01）的逻辑问题分析

### 问题 1：遗漏了 Liquipedia 核心数据源问题（★ 最严重）

**2026-08-01 方案未覆盖的根因**：Liquipedia 的 `{{Match}}` 模板中**根本没有 `bestof` 字段**。

通过实际抓取 1win Essence II 的 Liquipedia 页面源码证实：

```
===Group Stage===
...
{{Matchlist|id=...|title=July 30|width=340px|collapsed=false
|M1={{Match}}                          ← 无 bestof，无 opponent，空模板
|M2={{Match}}                          ← 无 bestof
|M3={{Match}}                          ← 无 bestof
|M4={{Match}}                          ← 无 bestof
|M5={{Match}}                          ← 无 bestof
}}
...
|M1={{Match
|opponent1={{TeamOpponent|LGD Gaming|score=W}}
|opponent2={{TeamOpponent|GamerLegion|score=FF}}
|date=July 31, 2026 - 11:00 {{Abbr/CEST}}
}}                                     ← 有 opponent/date，但依然无 bestof
```

**结论**：Liquipedia 编辑者通常**不在小组赛的 Match 模板中设置 `bestof`**，因为赛制已在 Format 节中统一说明。`parseMatchFields()` 在 `bestof` 缺失时默认 `bo = 1` → `BO1`，导致所有 Liquipedia 来源的小组赛对阵均被错误标记为 BO1。

**2026-08-01 方案中的 方案B（Liquipedia 交叉校正）完全失效**，因为它假设 Liquipedia 数据中有正确的 `bestof` 值，但实际数据中根本没有。

### 问题 2：RECENT 段 BO2 判定逻辑仍不完善

2026-08-01 方案提出的 groupSeries() 修复逻辑中，判定表存在歧义：

| 场景 | totalGames | Score | series_type | 旧逻辑 | 新逻辑(v1) |
|------|-----------|-------|-------------|--------|--------|
| BO2 2-0 全胜 | 2 | 2-0 | null | BO3 ✗ | **BO2** ✓ |
| BO3 2-0 横扫 | 2 | 2-0 | null | BO3 ✗ | **BO2** ⚠️（歧义） |

**歧义场景**：当 `series_type=null` 且 2 场比赛 2-0 时，无法区分是 BO2 还是 BO3。2026-08-01 方案的处理方式是「优先判定为 BO2」，但缺少来自 Liquipedia 数据的交叉验证支撑。

### 问题 3：Liquipedia 数据与 OpenDota 数据未形成闭环

- 2026-08-01 方案中的 方案B 仅从 Liquipedia 的 `bestof` 字段校正 OpenDota
- 但实际上 Liquipedia 的 `bestof` 缺失，方案B 没有数据来源
- 需要改为：**先通过 Format 节推断 BO 类型 → 再用于校正 OpenDota**

### 问题 4：配置过程未考虑 Format 节解析

Liquipedia 的 Format 节包含了完整的赛制说明，但当前代码完全未利用这一信息：

```
==Format==
*'''Group Stage''' ''(July 30 - August 2)''
**All matches are {{Abbr/Bo2}}       ← 明确标注小组赛全部 BO2
...
*'''Playoffs''' ''(August 3 - August 5)''
**Grand Final is {{Abbr/Bo5}}, all other matches are {{Abbr/Bo3}}
                                        ← 明确标注淘汰赛 BO3，总决赛 BO5
```

## 3. 修正后的根因分析

### 根因 1（★ 核心）：Liquipedia {{Match}} 模板缺少 `bestof` 字段

- 1win Essence II 小组赛的 `{{Match}}` 模板均未设置 `|bestof=2`
- Liquipedia 编辑者依赖 Format 节中统一说明赛制，不在每个 Match 模板中重复设置
- 当前 `parseMatchFields()` 在 `bestof` 缺失时默认 `bo = 1` → `BO1`
- **影响范围**：所有 Liquipedia 来源的赛程中，未在 Match 模板显式设置 bestof 的赛事

**诊断方法**：通过 `parseScheduledMatches` 返回的 `boType` 字段检查：若 `boType === 'BO1'` 但 `section === 'Group Stage'`，则大概率是 bestof 缺失导致的误判。

### 根因 2：OpenDota `series_type` 对 BO2 无对应值

- OpenDota 的 `series_type` 枚举值：0=BO1, 1=BO3, 2=BO5
- BO2 没有专用值，可能返回 `null`/`undefined`/`0`/`1`
- 当前代码 `st === 0 && totalGames === 2` 的严格等于条件排除了 `null`
- **影响范围**：所有 OpenDota 有数据且使用 BO2 赛制的赛事

### 根因 3：BO2 两场比赛可能不共享 `series_id`

- OpenDota 可能给 BO2 的两场比赛分配不同的 `series_id`（或 `series_id = 0`）
- 无 `series_id` 的比赛各自独立成组 → 被判为 BO1
- **影响范围**：OpenDota 数据中 `series_id` 缺失或分配不正确的 BO2 赛事

### 根因 4：Format 节信息未被利用

- Liquipedia 的 Format 节包含完整的赛制说明（阶段名→BO 类型映射）
- 当前代码完全未解析 Format 节
- **影响范围**：所有依赖 Liquipedia 赛程的赛事，当 Match 模板缺少 bestof 时

## 4. 修正后的优化方案

### 总体架构：四层递进判定

```
Layer 1: Format 节解析（liquipedia-parse.js）
  → 从 Format 节提取 phase→BO 映射
  → 如 { "Group Stage": "BO2", "Playoffs": "BO3", "Grand Final": "BO5" }

Layer 2: Match 模板解析（liquipedia-parse.js）
  → 解析 {{Match|bestof=...}} 模板
  → bestof 缺失时，用 section 字段匹配 Layer 1 的映射
  → 仍未匹配则默认 BO1

Layer 3: OpenDota groupSeries 判定（sources.js）
  → 修复 series_type null 时的 BO2 判定
  → 优先使用 series_type=1 明确标记的 BO3
  → 2 场比赛 + 2-0/1-1 → BO2

Layer 4: 跨源交叉校正（league-detail.js）
  → 用 Liquipedia 的 BO 类型（Layer 2 产出）校正 OpenDota 的 RECENT 数据
  → 仅校正 BO3→BO2 方向，避免误校正
```

### 方案 A（必做）：Format 节解析 + 阶段感知 BO 推断

**目标**：从 Liquipedia 的 Format 节提取 phase→BO 映射，用于 `{{Match}}` 模板 `bestof` 缺失时的兜底。

#### A1. 新增 `parseFormatBO()` 函数（`liquipedia-parse.js`）

```javascript
/**
 * 从 Format 节 wikitext 中提取 phase→BO 类型映射。
 * 
 * Liquipedia 的 Format 节结构示例：
 *   ==Format==
 *   *'''Group Stage''' ''(July 30 - August 2)''
 *   **All matches are {{Abbr/Bo2}}
 *   ...
 *   *'''Playoffs''' ''(August 3 - August 5)''
 *   **Grand Final is {{Abbr/Bo5}}, all other matches are {{Abbr/Bo3}}
 *
 * 解析规则：
 *   1. 扫描所有粗体阶段名（'''X'''），如 '''Group Stage''', '''Playoffs'''
 *   2. 在阶段名后查找 {{Abbr/BoN}} 或 "BoN" 模式
 *   3. "All matches are BoN" → 该阶段所有比赛均为 BoN
 *   4. "Grand Final is Bo5, all other matches are Bo3" → 细分规则
 *   5. "all other matches are Bo3" → 该阶段非总决赛的比赛为 Bo3
 *
 * 返回：{ phaseName: boType } 映射，如
 *   { "Group Stage": "BO2", "Playoffs": "BO3", "Grand Final": "BO5" }
 * 或 null（未找到 Format 节 / 无法解析）
 */
function parseFormatBO(wikitext) {
  if (!wikitext) return null;
  try {
    // 定位 ==Format== 节
    var fmtMatch = wikitext.match(/==\s*Format\s*==\s*\n([\s\S]*?)(?=\n==|$)/);
    if (!fmtMatch) return null;
    var fmtText = fmtMatch[1];
    
    var phaseMap = {};
    // 扫描阶段名：'''Group Stage''' 或 '''Phase Name'''
    var phaseRegex = /'''([^']+)'''/g;
    var phaseMatch;
    var lastPhaseName = '';
    var lastPhaseEnd = 0;
    
    // 先收集所有阶段名及其位置
    var phases = [];
    while ((phaseMatch = phaseRegex.exec(fmtText)) !== null) {
      phases.push({ name: phaseMatch[1].trim(), index: phaseMatch.index });
    }
    
    // 对每个阶段，在其后查找 BO 信息
    for (var i = 0; i < phases.length; i++) {
      var p = phases[i];
      var startIdx = p.index;
      var endIdx = (i + 1 < phases.length) ? phases[i + 1].index : fmtText.length;
      var block = fmtText.substring(startIdx, endIdx);
      
      // 查找 "All matches are BoN" 或 "all matches are BoN"
      var allMatch = block.match(/all\s+matches\s+are\s+(?:{{Abbr\/)?Bo(\d+)/i);
      if (allMatch) {
        phaseMap[p.name] = 'BO' + allMatch[1];
        continue;
      }
      
      // 查找 "Grand Final is Bo5, all other matches are Bo3"
      var gfMatch = block.match(/grand\s+final\s+is\s+(?:{{Abbr\/)?Bo(\d+)/i);
      var otherMatch = block.match(/all\s+other\s+matches\s+are\s+(?:{{Abbr\/)?Bo(\d+)/i);
      if (gfMatch && otherMatch) {
        phaseMap[p.name] = 'BO' + otherMatch[1];  // 非总决赛的默认赛制
        phaseMap['Grand Final'] = 'BO' + gfMatch[1];
        continue;
      }
      
      // 兜底：查找任何 "BoN" 模式
      var boFallback = block.match(/Bo(\d+)/);
      if (boFallback) {
        phaseMap[p.name] = 'BO' + boFallback[1];
      }
    }
    
    return Object.keys(phaseMap).length ? phaseMap : null;
  } catch (e) {
    return null;
  }
}
```

### 方案 B（必做）：修复 `groupSeries()` 的 BO2 判定逻辑

**目标**：修复 `series_type` 为 null/undefined 时的 BO2 误判，同时解决歧义场景。

**修改 `sources.js` `groupSeries()` 函数**：

```javascript
// 系列 BO 类型判定（基于胜负场数，比 series_type 更可靠）
// ★ 2026-08-03 修正：修复 series_type null 处理 + 歧义场景
// 规则：
//   series_type=2 或一方赢3局 → BO5（五局三胜）
//   series_type=1 → BO3（三局两胜，明确标记）
//   2场比赛 + 一方2-0 全胜 → BO2（双局积分制全胜）
//   2场比赛 + 1-1 平局 → BO2（双局积分制，BO3 不可能平局）
//   一方赢2局 → BO3（三局两胜，2-0 横扫或 2-1）
//   1场 → BO1
let boType = 'BO1';
const st = first.series_type;
const maxScore = Math.max(scoreA, scoreB);
const minScore = Math.min(scoreA, scoreB);
const totalGames = games.length;

if (st === 2 || maxScore >= 3) {
  // series_type=2 明确标记 BO5，或一方赢3局（BO3 不可能出现3胜）
  boType = 'BO5';
} else if (st === 1) {
  // series_type=1 明确标记 BO3
  boType = 'BO3';
} else if (totalGames === 2 && (maxScore === 2 || (scoreA === 1 && scoreB === 1))) {
  // ★ 2026-08-03 修正：合并 2-0 和 1-1 两种 BO2 场景
  //   - series_type=null/undefined/0 且 2 场比赛 → BO2
  //   - 2-0 全胜：双局积分制全胜
  //   - 1-1 平局：双局积分制平局（BO3 不可能平局）
  //   - series_type=1 已在上方被 BO3 分支拦截，不会走到这里
  //   歧义说明：BO3 2-0 横扫且 series_type=null 时，本分支会判定为 BO2。
  //   但此场景极罕见（OpenDota 对 BO3 赛事几乎总是设置 series_type=1），
  //   且后续可通过 Liquipedia 交叉校正（方案 C）二次修正。
  boType = 'BO2';
} else if (maxScore === 2) {
  // 一方赢2局但场数 > 2（如 2-0 但只有 2 场以外的情况）
  // 或 2-1 的 BO3
  boType = 'BO3';
} else if (maxScore === 1 && totalGames === 1) {
  boType = 'BO1';
} else {
  boType = 'BO1';
}
```

### 方案 C（推荐同步实施）：Liquipedia 交叉校正（增强版）

**目标**：利用 Liquipedia 的 `boType`（经方案 A 推断后的准确值）校正 OpenDota 的 BO 判定，解决歧义场景。

**与 2026-08-01 方案的关键区别**：
- 2026-08-01 方案：仅从 Liquipedia `bestof` 字段校正（数据源不可靠）
- 2026-08-03 方案：从 Format 节解析 + section 推断的 `boType` 校正（数据源可靠）

**修改 `league-detail.js`**：

```javascript
// ★ 2026-08-03 修正：Liquipedia BO 类型交叉校正（增强版）
// 使用 Liquipedia 经 Format 节解析 + section 推断后的 boType 校正 OpenDota 数据
// 校正方向：仅 BO3→BO2（避免 Liquipedia 推断错误导致误校正）
if (liqScheduled && liqScheduled.length && this.allSeries.length) {
  // 构建 Liquipedia 赛程的队名→BO 类型映射
  // 仅在 Liquipedia 的 boType 非 BO1（即不是默认兜底值）时参与校正
  var liqBOMap = {};
  liqScheduled.forEach(function (m) {
    if (m.team1Name && m.team2Name && m.boType && m.boType !== 'BO1') {
      var k = normalizeTeamNameForDedup(m.team1Name) + '__' + normalizeTeamNameForDedup(m.team2Name);
      var kRev = normalizeTeamNameForDedup(m.team2Name) + '__' + normalizeTeamNameForDedup(m.team1Name);
      var boVal = parseInt(m.boType.replace('BO', ''), 10) || 0;
      if (!liqBOMap[k] || parseInt(liqBOMap[k].replace('BO', ''), 10) < boVal) {
        liqBOMap[k] = m.boType;
        liqBOMap[kRev] = m.boType;
      }
    }
  });
  // 校正 OpenDota series 的 BO 类型
  this.allSeries.forEach(function (s) {
    // 仅校正 OpenDota 判定为 BO3 且 Liquipedia 为 BO2 的场景
    // 理由：
    //   1. BO5 有明确的 series_type=2，无需校正
    //   2. BO1 明确的单场赛事，无需校正
    //   3. BO3→BO2 是主要误判方向（歧义场景）
    if (s.boType !== 'BO3') return;
    var k = normalizeTeamNameForDedup(s.radiantName) + '__' + normalizeTeamNameForDedup(s.direName);
    var kRev = normalizeTeamNameForDedup(s.direName) + '__' + normalizeTeamNameForDedup(s.radiantName);
    var liqBo = liqBOMap[k] || liqBOMap[kRev];
    if (liqBo === 'BO2') {
      console.log('[liqBoCorrect] BO3→BO2 校正:',
        s.radiantName, 'vs', s.direName, 'score=', s.scoreA + '-' + s.scoreB);
      s.boType = 'BO2';
      s.boLabel = '双局积分';
      s.boTagCls = 'bo-bo2';
    }
  });
}
```
