## 2. 根因链（8 步，每步有据）

1. **OpenDota `/live` 在比赛结束后仍残留该局**：本例残留至 **2.7h 后**，`last_update_time` 已 **93 分钟**未变（数据不再更新）。
2. `pages/index/index.js` 的 `_applyMatchSources`（~L787）让 **`/live` 先入表** —— 这是 **2026-09-02 的有意设计**，
   其注释原话：**「对真实已结束的比赛 /live 早已不返回，**无副作用**」**
   ⇒ ★★ **该假设被实测推翻**（这正是本次事故的前提错误）。
3. `pushUnique` 用 `String(m.match_id)` 去重 ⇒ 后到的 **pro 已结算版本被 `seenId` 跳过**。
4. `_normalizeLiveMatch`（**L1047-1066**）**硬编码 `radiant_win: null`**
   ⇒ live 那一局**永远不可能计入任何一方的胜场**。
5. ⇒ 系列比分算成 **1 : 1**（少算了 9018525157 这一局）；`series_type=1`(BO3) **未达胜场**
   ⇒ `utils/sources.js:1341-1346` 的规则**强制 `isLive = true`**。
6. ⇒ 卡片 `status = live` + 比分 `1:1` —— **用户看到的异常**。
7. ⇒ **两条既有兜底同时失效**：
   - `isStaleLiveSeries`（`utils/sources.js:1234`）阈值 **3h**，本例仅 **2.7h** ⇒ 不触发；
   - 「比分判终局」（`utils/seriesStatus.isDecidedByScore`）用的**正是被污染的 1:1** ⇒ 判不出终局。
8. ⇒ **项目自带诊断也报绿**：`utils/diagnostics.js:128` 的「状态误判」判据是
   **「比分已达终局却仍是 live」** —— 它**共用被污染的比分** ⇒ 计数为 **0**
   ⇒ **这解释了"出现很多次却一直没被指标抓到"**（诊断与 bug 同源，不独立）。

### 为什么"出现很多次"（系统性）
任何 **BO3 打完后、`/live` 尚未清理** 的窗口内都会命中；且只要残留的正是**最后一局**（最常见形态），
比分就恰好少算一局 ⇒ 卡在"未达胜场"⇒ 判 live。**触发条件宽、窗口长（实测 ≥2.7h）⇒ 高频。**

## 3. 解决方案（分级 · 含精确落点）

### P0 治本：拒绝「已结束的 live 条目」顶掉已结算的 pro 条目
**落点**：`pages/index/index.js` `_applyMatchSources` 的 live 入表处（~L787-799）与 `pushUnique`（~L760）。

**权威判据（实测对照得出）**：

| 形态 | `deactivate_time` |
|---|---|
| 已结束的残留条目（本例） | **1790510377（≠ 0）** |
| 真正进行中的条目（3 条对照） | **0** |

⇒ **`/live` 的 `deactivate_time != 0` ⇒ 该 lobby 已结束**（Steam 原生字段）。

两种实现（**建议 A+B 组合**）：
- **A（最小）**：live 条目若 `deactivate_time` 非 0 ⇒ **不并入**（已结束的局交给 pro 侧权威数据）。
- **B（更稳）**：同 `match_id` 冲突时把**隐式「live 优先」改为显式仲裁** ——
  若 pro 侧**已结算**（`Number(duration) > 0 && radiant_win != null`）而 live 侧 `radiant_win == null`
  ⇒ **取 pro**；否则维持 live 优先。
  ⇒ 这样既保住 2026-09-02 的原修复意图（**真正进行中**的局仍以 live 为准），又修掉本例。

**预期**：本例比分 → **1:2**、`status` → **ended** ✓

### P1 独立兜底：series 层用「pro 已结算局」判终局
- 用 **pro 侧已结算局**独立算一次比分；若按 BO 已达胜场 ⇒ **强制 `ended` 且用该比分**。
- 价值：**不依赖** P0 的优先级逻辑正确；即使将来又出现别的污染路径也能兜住。

### P2 诊断补强（**必做**，否则同类问题继续报绿）
- 现状：`diagnostics.js` 的「状态误判」**共用被污染的比分** ⇒ **不独立**。
- 新增独立判据：**「存在 pro 已结算局、其胜场数已按 BO 达终局，而卡片 `status` 仍为 live」** ⇒ 计入误判。
- 并补 **SLO 目标 + 单测**（fixture 直接用本例真实数据）。

### P3 顺手（`_normalizeLiveMatch` 的硬编码）
- `radiant_win: null` 使"已结束的 live 条目"**永远无法自证**。
- 配合 P0，建议对 `deactivate_time != 0` 的条目**直接不产出**（或显式标记 `_deadLobby`），
  而不是产出一个"永远未结算"的假 match。
