# BO 系列赛制判定优化方案

> **日期**：2026-08-01 ｜ **状态**：待评审 ｜ **关联文件**：`utils/sources.js`、`subpackages/detail/league-detail/league-detail.js`、`utils/liquipedia-parse.js`

---

## 1. 问题描述

在赛事详情页的「对阵」模块中，LIVE/UPCOMING/RECENT 三段对局的 BO 赛制判定存在错误。以 **1win Essence II** 为例：

- 截至 2026-08-03 00:30（北京时间），该赛事所有比赛均为小组赛阶段
- 小组赛全部采用 **BO2（双局积分制）** 赛制
- 但赛事详情页中部分比赛显示为 **BO1** 或 **BO3**

---

## 2. 现状分析

### 2.1 BO 判定的数据流

```
OpenDota /leagues/{id}/matches
  → groupSeries() 按 series_id 分组
  → 根据 series_type + 场数 + 比分 判定 BO 类型

Liquipedia {{Match|bestof=2|...}}
  → parseScheduledMatches() 提取最佳 of 字段
  → boType = 'BO' + bestof
```

### 2.2 当前判定逻辑（`sources.js` `groupSeries()`）

```javascript
let boType = 'BO1';
const st = first.series_type;  // OpenDota: 0=BO1, 1=BO3, 2=BO5
const maxScore = Math.max(scoreA, scoreB);
const totalGames = games.length;

if (st === 2 || maxScore >= 3) {
  boType = 'BO5';
} else if (maxScore === 2) {
  if (st === 0 && totalGames === 2) {
    boType = 'BO2';  // ✓ 仅当 st===0 时判定为 BO2
  } else {
    boType = 'BO3';  // ✗ st 为 null/undefined 时误判
  }
} else if (maxScore === 1) {
  if (totalGames === 2 && scoreA === 1 && scoreB === 1) {
    boType = 'BO2';  // ✓ 1-1 平局正确判定
  } else {
    boType = 'BO1';  // ✗ 2 场单场各自独立时误判
  }
} else {
  boType = 'BO1';
}
```

### 2.3 Liquipedia 数据合并流程（`league-detail.js`）

```javascript
// 1. 先处理 OpenDota 数据
this.allSeries = sources.groupSeries(raw);  // BO 类型由 OpenDota 决定

// 2. 过滤 Liquipedia 赛程：剔除 OpenDota 已有的对阵
const liqSeries = liqScheduled.filter(function (m) {
  const k = dedupeKey(m.team1Name, m.team2Name);
  if (openDotaKeys.has(k) || openDotaKeys.has(kRev)) return false;  // 已存在 → 跳过
  return true;
});
```

## 3. 根因分析

### 根因 1：OpenDota `series_type` 对 BO2 无对应值（★ 核心）

OpenDota 的 `series_type` 字段枚举值只定义了：
- `0` → BO1
- `1` → BO3  
- `2` → BO5

**BO2 没有对应的 `series_type` 值**。对于 BO2 的双局比赛，OpenDota 可能返回：
- `series_type = null`（未设置）→ 当前代码 `st === 0` 不成立 → **误判为 BO3**
- `series_type = 0`（标记为 BO1）→ 当前代码 `st === 0` 成立 → 正确判定为 BO2（仅当 `totalGames===2` 时）
- `series_type = 1`（错误标记为 BO3）→ 当前代码走 else → **误判为 BO3**

**影响范围**：所有 OpenDota 有数据且使用 BO2 赛制的赛事（小组赛、循环赛等）。

### 根因 2：BO2 两场比赛可能不共享 `series_id`

OpenDota 可能给 BO2 的两场比赛分配不同的 `series_id`（或 `series_id = 0`）：
- 无 `series_id` 的比赛各自独立成组 → 每场作为独立系列 → 被判为 **BO1**
- 即使有 `series_id`，也可能因数据问题导致 `series_id` 不匹配

**影响范围**：OpenDota 数据中 `series_id` 缺失或分配不正确的 BO2 赛事。

### 根因 3：Liquipedia `bestof` 数据未用于 RECENT 段

Liquipedia 的 `{{Match|bestof=2}}` 模板正确标注了 BO2 信息，`parseScheduledMatches()` 也正确解析为 `BO2`。但在 `league-detail.js` 中：

- **UPCOMING/LIVE 段**：Liquipedia 数据穿透（因为 OpenDota 不返回未结束比赛），`boType` 正确显示为 `BO2`
- **RECENT 段**：Liquipedia 数据被去重逻辑过滤（因为 OpenDota 已有相同对阵的比赛），`boType` 来自 OpenDota 的 `groupSeries()`，可能不正确

### 根因 4：`series_type` 为 null 时的处理缺陷

当前代码中 `st === 0` 的条件是严格相等（`===`），排除了 `st = null` 或 `st = undefined` 的情况：

```javascript
if (st === 0 && totalGames === 2) {
  // 仅当 st 严格等于 0 时才进入 BO2
  // st = null 或 undefined 时条件不成立，走到 else 分支 → BO3（误判）
}
```

## 4. 优化方案

### 方案 A：修复 `groupSeries()` 的 BO2 判定逻辑（推荐，最小改动）

**目标**：修复 `series_type` 为 null/undefined 时的 BO2 误判。

**修改 `sources.js` `groupSeries()` 函数**：

```javascript
// 系列 BO 类型判定（基于胜负场数，比 series_type 更可靠）
// 规则：
//   一方赢3局 → BO5（五局三胜，BO3 不可能出现3胜）
//   一方赢2局 → BO3（三局两胜），除非 series_type 非明确 BO3 且恰好2场→BO2（双局积分全胜）
//   1-1 平局 → BO2（双局积分制，BO3 不可能平局）
//   1场 → BO1
let boType = 'BO1';
const st = first.series_type;
const maxScore = Math.max(scoreA, scoreB);
const minScore = Math.min(scoreA, scoreB);
const totalGames = games.length;

// ★ 2026-08-01 修复：BO2 判定逻辑增强
// OpenDota 的 series_type 枚举值：0=BO1, 1=BO3, 2=BO5
// BO2 没有对应的 series_type 值，OpenDota 可能返回 null/undefined/0/1
// 因此 series_type 仅作为参考，实际判定以场数和胜场为主
if (st === 2 || maxScore >= 3) {
  // series_type=2 明确标记 BO5，或一方赢3局（BO3 不可能出现3胜）
  boType = 'BO5';
} else if (st === 1) {
  // series_type=1 明确标记 BO3
  boType = 'BO3';
} else if (totalGames === 2 && maxScore === 2) {
  // ★ 修复：2 场比赛 + 一方 2-0 全胜
  //   - series_type=null/undefined/0 → BO2（双局积分制全胜）
  //   - series_type=1 已在上方被 BO3 分支拦截，不会走到这里
  boType = 'BO2';
} else if (totalGames === 2 && maxScore === 1 && scoreA === 1 && scoreB === 1) {
  // 2 场比赛 + 1-1 平局 → BO2（双局积分制，BO3 不可能平局）
  boType = 'BO2';
} else if (maxScore === 2) {
  // 一方赢2局但场数 > 2（如 2-0 但只有 2 场以外的情况，如 2 场但 st===1 已被拦截）
  // 或 2-1 的 BO3
  boType = 'BO3';
} else if (maxScore === 1 && totalGames === 1) {
  boType = 'BO1';
} else {
  boType = 'BO1';
}
```

**判定逻辑对照表**：

| 场景 | totalGames | Score | series_type | 旧逻辑 | 新逻辑 |
|------|-----------|-------|-------------|--------|--------|
| BO2 2-0 全胜 | 2 | 2-0 | null | BO3 ✗ | **BO2** ✓ |
| BO2 2-0 全胜 | 2 | 2-0 | 0 | BO2 ✓ | BO2 ✓ |
| BO2 2-0 全胜 | 2 | 2-0 | 1 | BO3 ✗ | BO3 ✓（保留） |
| BO2 1-1 平局 | 2 | 1-1 | 任意 | BO2 ✓ | BO2 ✓ |
| BO3 2-0 横扫 | 2 | 2-0 | 1 | BO3 ✓ | BO3 ✓ |
| BO3 2-1 决胜 | 3 | 2-1 | 1 | BO3 ✓ | BO3 ✓ |
| BO3 2-0 横扫 | 2 | 2-0 | null | BO3 ✗ | **BO2** ⚠️（歧义） |
| BO1 单场 | 1 | 1-0 | 任意 | BO1 ✓ | BO1 ✓ |

> ⚠️ **歧义说明**：当 `series_type=null` 且 2 场比赛 2-0 时，无法区分 BO2（2-0 全胜）和 BO3（2-0 横扫）。新逻辑在此场景下优先判定为 BO2，因为：
> 1. OpenDota 对 BO3 赛事通常正确设置 `series_type=1`（尤其是 DPC/Major/ESL 等大型赛事）
> 2. `series_type=null` 更常见于小组赛/循环赛等 BO2 场景
> 3. 如果确实为 BO3 且 `series_type` 缺失，影响较小（仅显示标签差异，不影响功能）

### 方案 B：Liquipedia `bestof` 数据交叉校正（增强方案，推荐同步实施）

**目标**：利用 Liquipedia 的 `bestof` 字段校正 OpenDota 的 BO 判定，解决歧义场景。

**修改 `league-detail.js`**：在合并 Liquipedia 数据时，将 Liquipedia 的 `boType` 回写到匹配的 OpenDota series 上。

```javascript
// ★ 2026-08-01 新增：Liquipedia BO 类型校正
// 在合并 Liquipedia 赛程之前，使用 Liquipedia 的 bestof 数据校正 OpenDota 的 BO 判定
// 原因：OpenDota 的 series_type 对 BO2 无对应值，可能导致误判
// Liquipedia 的 bestof 字段直接来自赛事页面，更准确
if (liqScheduled && liqScheduled.length && this.allSeries.length) {
  // 构建 Liquipedia 赛程的队名→BO 类型映射（取 bestof 最高的值）
  var liqBOMap = {};  // key: 'team1Name__team2Name' → boType
  liqScheduled.forEach(function (m) {
    if (m.team1Name && m.team2Name && m.boType && m.boType !== 'BO1') {
      var k = normalizeTeamNameForDedup(m.team1Name) + '__' + normalizeTeamNameForDedup(m.team2Name);
      var kRev = normalizeTeamNameForDedup(m.team2Name) + '__' + normalizeTeamNameForDedup(m.team1Name);
      // 取最高 BO 值（BO5 > BO3 > BO2 > BO1）
      var boVal = parseInt(m.boType.replace('BO', ''), 10) || 0;
      if (!liqBOMap[k] || parseInt(liqBOMap[k].replace('BO', ''), 10) < boVal) {
        liqBOMap[k] = m.boType;
        liqBOMap[kRev] = m.boType;
      }
    }
  });
  // 校正 OpenDota series 的 BO 类型
  this.allSeries.forEach(function (s) {
    if (s.boType === 'BO1') return;  // BO1 无需校正（BO1 是明确的）
    var k = normalizeTeamNameForDedup(s.radiantName) + '__' + normalizeTeamNameForDedup(s.direName);
    var kRev = normalizeTeamNameForDedup(s.direName) + '__' + normalizeTeamNameForDedup(s.radiantName);
    var liqBo = liqBOMap[k] || liqBOMap[kRev];
    if (liqBo && liqBo !== s.boType) {
      // 仅在 OpenDota 判定为 BO3 而 Liquipedia 为 BO2 时校正（排除 BO5 等明确场景）
      // 避免 Liquipedia 数据不准确导致的误校正
      if (s.boType === 'BO3' && liqBo === 'BO2') {
        console.log('[liqBoCorrect] BO3→BO2 校正:', s.radiantName, 'vs', s.direName, 'key=', k);
        s.boType = 'BO2';
        s.boLabel = '双局积分';
        s.boTagCls = 'bo-bo2';
      }
    }
  });
}
```

**校正条件**：
- 仅在 OpenDota 判定为 BO3 而 Liquipedia 为 BO2 时校正
- 不校正 BO1（BO1 明确的单场赛事）
- 不校正 BO5（BO5 有明确的 `series_type=2`）
- 不处理 Liquipedia 无数据的系列

### 方案 C：场景关联匹配（解决 `series_id` 缺失导致的 BO1 误判）

**目标**：当两场比赛在短时间内（如 2h 内）由相同两队进行但无 `series_id` 时，将其关联为同一系列。

**修改 `sources.js` `groupSeries()` 函数**：在按 `series_id` 分组后，增加场景关联匹配。

```javascript
// ★ 2026-08-01 新增：场景关联匹配
// 对于已按 series_id 分组后的单场系列（BO1），检查是否存在相同两队
// 在 2h 内进行的另一场比赛，若有则合并为 BO2 系列
// 解决 OpenDota 未正确分配 series_id 导致 BO2 被拆分为 2 个 BO1 的问题
function mergeOrphanMatches(seriesList) {
  if (!seriesList || seriesList.length < 2) return seriesList;
  var merged = [];
  var used = new Set();
  for (var i = 0; i < seriesList.length; i++) {
    if (used.has(i)) continue;
    var s = seriesList[i];
    // 只处理单场未分组的系列（无 series_id 或 series_id=0）
    var isOrphan = s.games.length === 1 && 
      (s.games[0].series_id == null || s.games[0].series_id === 0);
    if (!isOrphan) {
      merged.push(s);
      continue;
    }
    // 查找相同两队、时间相近的孤场比赛
    var found = -1;
    var tA = s.radiantName, tB = s.direName;
    var tStart = s.games[0].start_time || 0;
    for (var j = i + 1; j < seriesList.length; j++) {
      if (used.has(j)) continue;
      var s2 = seriesList[j];
      if (s2.games.length !== 1) continue;
      var s2tA = s2.radiantName, s2tB = s2.direName;
      // 队名匹配（相同两队，不分主客）
      var match = (tA === s2tA && tB === s2tB) || (tA === s2tB && tB === s2tA);
      if (!match) continue;
      var s2Start = s2.games[0].start_time || 0;
      // 2h 内的时间窗口
      if (Math.abs(s2Start - tStart) < 2 * 3600) {
        found = j;
        break;
      }
    }
    if (found >= 0) {
      // 合并两场比赛为 BO2 系列
      var g2 = seriesList[found].games[0];
      s.games.push(g2);
      s.games.sort(function(a, b) { return (a.start_time || 0) - (b.start_time || 0); });
      // 重算比分
      s.scoreA = 0; s.scoreB = 0;
      s.games.forEach(function(g) {
        if (g.radiant_win) s.scoreA++; else if (g.radiant_win === false) s.scoreB++;
      });
      s.boType = 'BO2';
      s.boLabel = '双局积分';
      s.boTagCls = 'bo-bo2';
      s.isMulti = true;
      used.add(found);
    }
    merged.push(s);
  }
  return merged;
}
```

**在 `groupSeries()` 末尾调用**：

```javascript
// 在 order.map(...) 之后、return 之前调用
const mergedList = mergeOrphanMatches(list);
return mergedList;
```

### 方案 D：Curation 层 BO 格式覆盖（可选，长远规划）

**目标**：在 curation 数据中增加 `seriesFormat` 字段，为已知赛事指定 BO 格式。

**修改 `curation.js`**：

```javascript
{ canonical: '1win Essence II', tier: { grade: 'S', rank: 3, label: 'S级' },
  aliases: ['1win Essence 2', '1win essence ii', '1win Essence'],
  year: 2026,
  start: ..., end: ...,
  liquipediaSlug: '1win_Essence/2',
  seriesFormat: 'BO2'  // ★ 新增：指定该赛事默认 BO 格式
},
```

**`seriesFormat` 字段规范**：
- 可选值：`'BO1'` / `'BO2'` / `'BO3'` / `'BO5'` / `null`（不指定）
- 指定后，在该赛事的所有对阵中，当 OpenDota 数据无法明确判定 BO 类型时，优先使用此值
- 仅作为兜底/参考，不强制覆盖（因为同一赛事可能混用不同 BO 格式，如小组赛 BO2 + 淘汰赛 BO3）

**在 `sources.js` 中应用**：

```javascript
// 在 groupSeries 中，判定 BO 类型时参考 curation 的 seriesFormat
function getSeriesFormat(leagueName) {
  var cur = curation && curation.curatedEventFor 
    ? curation.curatedEventFor(leagueName, { game: 'dota2' }) 
    : null;
  return (cur && cur.seriesFormat) || null;
}
```

## 8. 附录：OpenDota `series_type` 字段说明

| series_type | OpenDota 含义 | 实际使用场景 |
|------------|-------------|-------------|
| 0 | BO1 | 单场决胜，或 BO2（BO2 无专用值，复用 0） |
| 1 | BO3 | 三局两胜 |
| 2 | BO5 | 五局三胜 |
| null/undefined | 未设置 | 常见于 BO2 赛事，或历史数据不完整 |

**关键发现**：OpenDota 的 `series_type` 字段对 BO2 支持不完整，无法仅靠此字段准确判定 BO2。必须结合比赛场数、比分和 Liquipedia 辅助数据综合判定。
