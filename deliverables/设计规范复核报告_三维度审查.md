## 一、合理性审查

### P0-1：`grid` 图标在 TDesign 中不存在 ❌【必须修正】

**文档声称**（§3.2）：
> 首页 `home` → **`grid`**（四宫格=数据面板入口）

**实际核查**：在 `miniprogram_npm/tdesign-miniprogram/icon/icon.wxss` 中搜索：
- `t-icon-grid` → **不存在**
- 存在的是 `t-icon-grid-add`、`t-icon-grid-add-filled`、`t-icon-grid-view`、`t-icon-grid-view-filled`

**影响**：如果直接使用 `grid` 作为 icon name，TabBar 首页将渲染为空白图标。

**修正方案**：
- 首页图标改用 **`grid-view`**（四宫格浏览，语义最贴合）
- 或保留 `home`（当前已验证可用），只是调整选中态权重

---

### P0-2：`clip-path` 在低版本微信基础库不支持 ❌【必须修正】

**文档声称**（§4.4）：
> 所有方案均用纯 CSS 实现（不需要外部图片文件），方案 A 使用 `clip-path: polygon(...)` 裁剪六边形

**实际核查**：根据微信小程序兼容性资料：
- **基础库 < 2.25.2** 不支持 `clip-path`，会静默忽略该样式
- 部分 Android WebView（低版本）也存在不支持的情况
- 微信小程序的用户基础库版本由微信客户端版本决定，无法控制

**影响**：低版本微信用户的 LOGO 会显示为一个方形色块（clip-path 被忽略），而非六边形棱镜——设计意图完全丢失。

**修正方案**（按推荐顺序）：
1. **方案 A：用 `transform: rotate()` + `overflow: hidden` 模拟六边形**（兼容性最好）
   - 外层 view 设 `overflow: hidden` + `border-radius`，内层用两个三角形伪元素遮挡
2. **方案 B：降级为 SVG 内联背景**（`background-image: url(data:image/svg+xml,...)`）
   - 注意 URL 转义和 data URI 长度限制
3. **方案 C：直接用方形 + 金色描边 + 内部三角色**（放弃六边形，但 100% 兼容）
   - 纯 `border` + `::after` 三角形，无 clip-path 依赖

---

### P0-3：TabBar 未选色 `#5a5a62` 对比度严重不足 ❌【必须修正】

**文档声称**（§1.6）：
> TabBar 未选色 `#5a5a62`（暗化未选状态，让选中态更突出）

**WCAG 对比度计算结果**（`#5a5a62` on `#0d0d0d`）：

| 元素 | 对比度 | WCAG AA 要求 | 判定 |
|---|---|---|---|
| TabBar 未选图标 | **1.58:1** | ≥ 3:1（图标/图形） | ❌ 不达标 |
| TabBar 选中图标 `#FFD15C` | **2.40:1** | ≥ 3:1 | ❌ 不达标 |

**影响**：在近黑底上，`#5a5a62` 几乎不可见——暗化未选态的想法是对的，但步子迈太大了。用户在强光环境下可能完全看不到未选中的 Tab。

**修正方案**：未选色改为 **`#6b6b73`** 或 **`#707078`**（对比度约 2.2:1~2.5:1，虽然仍不满足 AA 图标 3:1，但至少在视觉上可辨；如果要严格达标，需要 `#8a8a92` 以上，但这又会削弱选中态的对比效果）。

> **设计权衡说明**：暗色系 TabBar 的未选态对比度是一个经典的可达性难题——完全满足 WCAG AA 3:1 要求会让未选态过亮，失去选中态的视觉优先级。建议在文档中明确标注这是 **有意为之的可接受性权衡**，而非疏忽。

---

### P0-4：已结束卡片 55% 透明度导致文字不可读 ❌【必须修正】

**文档声称**（§1.4）：
> 已结束整体降至 55%，像舞台灯光渐暗
> `.league-item--ended { opacity: 0.55; }`

**WCAG 对比度计算结果**：

| 场景 | 有效对比度 | WCAG AA 要求 | 判定 |
|---|---|---|---|
| 主文字 `#f0f3f6` at 55% opacity on `#0d0d0d` | **~2.7:1** | ≥ 4.5:1 | ❌ 不达标 |

**影响**：已结束的赛事信息（赛果、日期等）对用户仍有参考价值。55% 透明度让所有文字对比度降到不可读的程度。

**修正方案**：
- 方案 A：改用 **70% 透明度**（主文字有效对比度约 4.0:1，接近 AA）
- 方案 B：不用整体 opacity，改为只暗化**装饰元素**（Tier 色带、徽章），文字保持原色但降低 font-weight
- 方案 C：分元素处理：文字 80% + 背景 60% + Tier 色带 40%

---

### P1-1：`--bg-stage` 和 `--bg-stage-grad` Token 命名与现有体系不一致 ⚠️【建议修正】

**问题**：文档 §1.1 引入了两个新 token 名 `--bg-stage` 和 `--bg-stage-grad`，但：
1. 当前代码中不存在这两个 token（grep 确认零引用）
2. 现有体系用的是 `--td-bg-color-page`（TDesign 标准 token）

**影响**：如果新增 `--bg-stage` 但不同步更新 `--td-bg-color-page`，会导致两个 token 指向不同的值，TDesign 组件和自定义样式可能出现底色不一致。

**修正方案**：
- 直接更新 `--td-bg-color-page` 的值，不引入新 token 名
- 或者引入 `--bg-stage` 作为 `--td-bg-color-page` 的别名（两者同步更新）

---

### P1-2：Tier 色浸染渐变在卡片底色上的对比度不足 ⚠️【建议修正】

**文档声称**（§1.2）：
> 卡片左侧 5px 纯色带 → 向右 80px 浸染衰减到透明，alpha 值 0.06~0.10

**核查**：在 `#1a1a1e` 卡片底上，0.08 alpha 的 Tier 色几乎不可见（计算表明色差仅 1~2 个 RGB 单位）。

**影响**：「向右 80px 浸染」是文档反复强调的**核心设计特征**，但实际渲染效果可能微弱到用户感知不到——尤其是 S 级（暗金 `#C8A951`）在深底上浸染效果最弱。

**修正方案**：
- 浸染 alpha 从 0.06~0.10 提升到 **0.12~0.18**
- 或者浸染距离从 80px 缩短到 **50px**（让衰减更集中、更可见）
- 建议在开发者工具真机预览后再定稿

---

### P1-3：卡片圆角从 16rpx → 14rpx 改动理由不充分 ⚠️【建议修正】

**文档声称**（§1.2）：
> `--card-radius`：16rpx → **14rpx**（略微收窄圆角，更锐利）

**问题**：
1. `--card-radius` 这个 token 在现有代码中**不存在**（grep 确认零引用），卡片圆角是在各组件里硬编码的 `16rpx`
2. 改动理由"更锐利"过于主观——14rpx 和 16rpx 在视觉上差异极小（仅 0.5px @2x），但会牵连所有使用了 `border-radius: 16rpx` 的组件
3. 如果只改 token 但组件硬编码不更新，会出现 token 和实际值不一致

**修正方案**：要么删除这条改动（保持 16rpx），要么补充完整的批量替换计划。

### P1-4：「浏览历史」功能不存在，快捷区引用了未实现的功能 ⚠️【建议修正】

**文档声称**（§2.2 快捷功能区）：
> · 关注战队 · 关注赛事
> · 赛事提醒 · 浏览历史

**核查**：搜索全项目，**不存在浏览历史功能的任何代码**（无存储、无读取、无页面）。

**影响**：快捷功能区放了 4 个入口，但其中「浏览历史」点击后会跳转到不存在的页面。

**修正方案**：
- 移除「浏览历史」，替换为已有功能（如「搜索」、「设置」）
- 或者标注为「待实现」，Phase 3 只搭建 UI 框架，点击后 toast 提示"功能开发中"

## 二、逻辑性审查

### ✅ 合理之处

1. **实施顺序正确**：Phase 1（全局基础）→ Phase 4（标杆页）→ 用户验收 → 批量适配。先做标杆页验收再批量推广是正确的工程实践。
2. **设计语言主张清晰**：「黑暗赛场聚光灯」的一一句话概括准确，三层设计原则（内容是主角、颜色编码功能化、亮度即优先级）逻辑自洽。
3. **Token 分层合理**：底色 → 卡片 → Tier 浸染 → 亮度分层，从大到小的层次结构清晰。
4. **TabBar 图标语义分析到位**：每个图标的更换都有语义说明，不是随意替换。

### ⚠️ 需要补充的逻辑缺口

#### P1-5：Phase 4.1 依赖未说明的 JS 改动

**文档声称**（§5 Phase 4.1）：
> `pages/leagues/leagues.wxml`：LIVE 卡片加 `league-item--live` 类名

**核查**：当前 `leagues.wxml` 第 147 行的卡片类名是 `league-item {{item.tierClass}} anim-fade-up`，**不存在 `--live` 或 `--ended` 类名**。这意味着：
- Phase 4.1 不仅需要改 WXML，还需要改 `leagues.js` 中的 `buildLeagueItem()` 或类似函数，让它根据 `item.status` 动态添加 `--live`/`--ended` 类名
- 文档没有提到这个 JS 改动

**修正建议**：Phase 4 应拆分为 4a（JS 状态类名注入）+ 4b（WXSS 浸染效果），并明确列出 `leagues.js` 的改动点。

#### P1-6：Phase 3「我的」模块改动范围被低估

**文档声称**（§5 Phase 3）：
> 3.1 `pages/follow/follow.wxml`：重构页面结构
> 3.2 `pages/follow/follow.wxss`：全量重写
> 3.3 `pages/follow/follow.js`：新增快捷功能区数据和设置项数据

**核查**：当前 `follow.js` 有 ~400 行代码，包含订阅管理、提醒策略、A/B 实验、登录态等复杂逻辑。「全量重写」WXSS + 「新增数据」JS 看起来轻描淡写，但实际改动量可能很大：
- 快捷功能区需要新增 4 个点击处理函数
- 「其他设置」需要新增隐私协议跳转、缓存清除、版本号读取等逻辑
- 浏览历史功能不存在（见 P1-4），需要决定是否新建

**修正建议**：Phase 3 应标注为 **「高复杂度」**，并拆分为 3a（用户卡片 + 快捷功能区 UI）→ 3b（关注列表适配新设计语言）→ 3c（设置区功能实现），每步独立验收。

#### P1-7：跨页面一致性影响未评估

**文档 Phase 6** 列出了其他页面的适配，但没有评估：
- **搜索页**（`pages/search/search`）：搜索结果卡片是否也用 Tier 浸染？如果是，Phase 6.3 需要更详细的说明

- **英雄/物品详情页**：这些页面的卡片结构与赛事卡片完全不同，Tier 浸染是否适用？

**修正建议**：补充一个「设计语言适用范围矩阵」，明确哪些组件使用 Tier 浸染、哪些不使用。

## 三、合规性审查

### ✅ 合规之处

1. **LOGO 方案 A 六边形棱镜**：不使用 Valve 官方盾形、不使用官方字体、LOGO 本身不含"DOTA2"文字——合规分析准确。
2. **"DOTA2赛事" 作为描述性文字使用**：这是商标法下的"描述性合理使用"（descriptive fair use），只要不暗示官方背书即可。
3. **原创几何符号**：六边形 + 棱镜三角色是完全原创的设计元素，不构成对任何 Valve 知识产权的侵犯。

### ⚠️ 需要修正的合规问题

#### P0-5：版权引用来源张冠李戴 ❌【必须修正】

**文档声称**（§4.2）：
> 根据 Valve 官方政策（[Video Policy](https://www.valvesoftware.com/videopolicy.html) + [Fan Content Guidelines](https://futurlab.freshdesk.com/support/solutions/articles/204000072433-our-fan-content-guidelines)）

**核查**：
- `Video Policy` 确实是 Valve 官方页面 ✅
- **但 `Fan Content Guidelines` 是 Futurlab（另一个游戏公司）的政策页面，不是 Valve 的** ❌

**影响**：引用了错误的版权来源，虽然结论（原创设计合规）是正确的，但论据不可靠会降低文档的可信度。

**修正方案**：
- 移除 Futurlab 的 Fan Content Guidelines 引用
- 替换为 Valve 官方的 [DOTA 2 Community Stream Policy](https://www.dota2.com/dotatv) 或 [Limited Game Event License Agreement](https://csgo.5eplay.com/article/2512113lhys9) 作为参考
- 实际上 Valve 没有发布过明确的 "Fan Content Guidelines"——这一点本身就应该在文档中说明（Valve 的政策散落在多个页面中，没有统一文档）

---

### 补充合规建议

1. **小程序名称和描述**：确保小程序在微信平台的注册名称、描述、关键词中不使用"官方"字样，不暗示与 Valve 的关联。
2. **用户协议和隐私政策**：在「关于我们」中声明本小程序为第三方非官方工具，所有商标归原权利人所有。
3. **赛事数据来源声明**：在资料页或设置页标注数据来源（OpenDota、STRATZ、Liquipedia），这既是学术规范也是合规加分项。

## 五、结论

这份设计规范在**设计主张和方向选择**上是成功的——「黑暗赛场聚光灯」的理念清晰、有辨识度、符合产品定位。但在**工程落地细节**上存在 5 个必须修正的硬伤（图标不存在、clip-path 不兼容、对比度不达标、引用来源错误），如果不修正就直接开工，会导致：

1. TabBar 首页图标空白（P0-1）
2. 低版本微信用户 LOGO 显示异常（P0-2）
3. 未选 Tab 和已结束卡片不可读（P0-3/P0-4）
4. 版权分析可信度受损（P0-5）

**建议**：先修正 5 项 P0，再补充 7 项 P1，然后按修正后的版本进入实施。
