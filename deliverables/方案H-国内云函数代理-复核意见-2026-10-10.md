## 2. 具体方案（草案，含客户端接入点）

### 2.1 云函数职责（Node.js，约 80 行）
```
入参：{ path: '/proMatches' | '/leagues' | '/teams/123' | '/explorer?sql=…', query }
流程：① DoH(223.5.5.5) 解析 api.opendota.com → 真实 IP（可缓存 5 分钟）
      ② https 请求 真实IP:443，servername/Host = api.opendota.com → 拿 JSON
      ③ 短时缓存（同 EF 的策略：/proMatches 5min、/leagues 6h）—— 同时**替客户端省 OpenDota 配额**
      ④ 只放行 OpenDota **只读白名单路径**，拒绝任意 URL（防成开放代理）
返回：{ data } 或 { error }
```

### 2.2 客户端接入点（**一处**，改动小）
`utils/api.js` 的**直连通道** `rawRequest()`（第 66 行起）：
```
现：url = BASE + path                 // api.opendota.com（被劫持）
改：url = CLOUD_FN_BASE               // 云函数（云开发：wx.cloud.callFunction；HTTP：国内域名）
```
⇒ **所有 41 个 api 方法自动受益**（它们都最终走 `request → rawRequest`），**无需逐个改** ✓
⇒ 另需：把云函数入口**作为 `tryCloudOrDirect` 的第三条兜底**（EF ✗ → 云函数 ✓），避免直接替换带来的风险。

### 2.3 安全与配额
- 只放行只读路径白名单；不带任何密钥到客户端（云函数侧无需 key，OpenDota 免费无需 token）；
- 云函数侧缓存 + 节流（OpenDota 限 60/min）⇒ 客户端高并发也不会打爆。

## 3. ★★ 关键复核：**"只做 OpenDota 代理"够不够？—— 不够**

按"数据来源"回代码逐条核对（`api.js` + `remoteCuration.js` + `liquipedia.js` + `cloudSync.js`）：

### ✅ 能恢复的（OpenDota 经云函数）
| 功能 | 依据 |
|---|---|
| 首页对局（`/proMatches`、`/live`） | `getProMatches/getLiveMatches` → `tryCloudOrDirect` → 直连通道 |
| 赛事列表（`/leagues` + `/explorer` 窗口） | `getLeagues/getLeagueWindows` |

⇒ **可见数据的主体在 OpenDota 一侧 ⇒ 这部分确实能恢复** ✓（这也是我原话的依据）

### ❌ **不能**恢复的（仍依赖被 SNI 阻断的 Supabase）
| 功能 | 现状 | 影响 |
|---|---|---|
| **远端 curation 热更新**（`remoteCuration` 读 `curation_events/teams/meta`） | `catch → return null` ⇒ **退回包内本地 curation**（`utils/curation.js` 85KB ✓ 在包内） | **功能不崩、但"不能远端热更新"** ⇒ 赛事分级/别名/焦点卡的权威覆盖要**随发版**更新 |
| **云端队标**（`liquipedia._sbLogoGet` 读 `aggregation_cache`） | 失败 ⇒ null | 本地 `team-logo-local-data.js`（140KB）已覆盖 ⇒ **影响小** |
| **云同步**（`cloudSync`：关注列表/订阅状态） | 默认 **off**（只写本地、零请求） | **影响小** |
| **LP / STRATZ 经 EF 的路径**（`liquipedia-proxy`/`stratz-proxy`） | 仍失效（真机日志已证） | LP 有 **haglund 直连兜底 ✓**（日志实测命中 9 场）⇒ 部分可用 |
| **远端指标/心跳**（`curation_meta`） | 失败 | 「数据健康」卡显示异常（不致命） |

### ★ 结论（修正我原来的说法）
> **H 能恢复"赛事/比赛/战队/英雄/物品"这一大类可见数据**，
> **但不能恢复"远端 curation 热更新 / 云端队标 / 云同步"** ⇒
> **完整方案 = H（OpenDota 代理） + curation 走"本地/烘焙"**（即方案 G 的那一半）✓
> **我原表述"立刻恢复赛事/比赛数据"应改为**：**"立刻恢复绝大多数可见数据；curation 类的远端热更新需另配（本地已有兜底，可用）"**。
