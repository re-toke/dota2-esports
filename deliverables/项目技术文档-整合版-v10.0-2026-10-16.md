## 1. 项目概览

### 1.1 产品定位
DOTA2 赛事信息微信小程序：**关注 S 级及以上赛事**、查看**战队 / 队员资料**、对比**双方历史交锋**；含赛事列表（进行中/即将/已结束 + 等级筛选 + 智能排序）、赛事详情（对阵三态 LIVE/UPCOMING/RECENT + BO 判定 + 比分实时）、全局搜索、关注订阅（赛前提醒）、资料库（英雄/物品）。
**第三方非官方粉丝工具**：仅展示公开电竞数据，**无付费 / 无广告 / 无用户生成内容**。

## 3. 核心数据链路

### 3.1 赛事级状态判定（`util.js` isOngoing / isUpcoming / statusOf）
- 三路径：① OpenDota 真实结束时间（`lastEnd`）在缓冲内 ② curation 日期窗 ③ 未结算兜底；`config.leagueWindow.ongoingBufferSec=2h`。
- `LEAGUE_WINDOWS_SQL` 含 `max(start_time+duration) AS last_end`（真实结束时间，禁只用 latest）。
- **⚠️ curation status 硬覆盖守卫**：curation status 是开赛初值（赛事结束后无人回改 → 永久僵尸）。三处硬覆盖点（`leagues.js normalize` + `league-detail.js _renderLocalSkeleton` + `load()`）统一加守卫：「已结束」永远信任；「进行中」须 `isOngoing`；「即将到来」须 `isUpcoming`。**核心原则：静态字段若不随时间流转，不能盖掉基于时间的判定**（三处须字节级一致）。
- **⚠️ OpenDota `tier=professional` 脏数据双保险**：① 黑名单 `curation.EXCLUDE_LEAGUE_IDS`（按 leagueid，如 16251）；② 跨度阈值 `config.leagueWindow.maxSpanSec=365d`，`util.validateLeagueWindow(win, ctx)` 跨度超阈值且未在 curation 命中（非人工策展）即清零窗口字段（不传 ctx 退化为旧行为）。

### 3.1b 对阵级 phase 推断（含根因 J 顺延守卫）
- **phase 推断三档**（`utils/haglund.js` + `utils/liquipedia-parse.js` + `league-detail.js` LIVE 段过滤，字节级镜像铁律 G14）：
  - `start > nowSec + 5min` → **upcoming**（5min 缓冲防时钟漂移）
  - `elapsed = nowSec - start`；`elapsed < 6h` → **live**；`elapsed ≥ 6h` → **recent**（防僵死数据）
- **★ 根因 J · 实际开赛证据守卫**：DOTA2 赛事顺延是常态，phase 推断**不能只依赖规划时间**；`phase==='live'` 时必须满足任一「实际开赛证据」才允许进 LIVE 段，否则降回 UPCOMING（详见 §3.5）。
- **上游侧同步**：`utils/haglund.js` 阈值改为 `start ≤ nowSec - 5min - 15min`（叠加顺延容忍）。

### 3.2 BO 判定引擎（`sources.js`）
- 入口：`buildBoContext` + `resolveBoType` + `applyBo` + `patchNullSeriesId` + `getSeriesKey`；league-detail `buildSeriesFromSources` 统一后处理（B4 轮询实时重算）。
- **信号优先级（禁比分反推）**：S1 每场声明 → S2 赛制文本（`parseBoFormat`/format 关键词，uniBo 仅 group/playoff 非空且相等才权威；curation boFormat）→ S3 `series_type`（0=BO1/1=BO3/2=BO5/3=BO2）→ **S4.5 mapSlots 槽位信号**（仅 `st==null && !s2Auth`）→ S4 同日粒度自证 → S5 约束（2:0 零信号保守 BO3；`isDraw` 三重重算）→ S6 默认（playoff→BO3，其余→RECENT 众数→BO1）。
- **`patchNullSeriesId`**：OpenDota 偶发 `series_id=null` 拆两张卡的客户端兜底。根因 G 强化：合格邻居 `count≥2 → count≥1`（前提 `series_type≥1`）；双向对称 **6h 时间窗**（前侧 30min + 后侧 6h）；防误并靠「同队 ID 对不计顺序 + `series_type=0` 的 BO1 邻居永不并 + 6h 上限」；软关联 `_patchedSeriesKey` + 全局开关 `PATCH_NULL_SERIES_ENABLED`。
- **`groupLiquipediaMatches`**：Liquipedia/LPDB 来源独立聚合入口（修「一场 BO3 拆成 N 张 BO1 卡」）。聚合键 `series_id` 优先；缺失用「队名对(顺序无关)+UTC 同日」兜底合成 `orphan_`；合并规则：最早 startTime、最高 phase、总分最大场为系列比分、matchIds 去重。⚠️ 边界 `day===0` 已改用 `st > 0` 判定。
- **阶段划分 R4**：LP `section` 锚点（liqStages，|ΔT|<24h 守卫）优先；OpenDota 时间簇边界 = `series_type` 突变或主导局数变化≥2 且日历日差≥1。
- **坑**：① 不能凭赛事名推断赛制，必须信 LP Format 段；② `fmt()` 驼峰 `radiantWin` → `settledCountOf` 兼容两字段；③ **双源一致性（G14）**：服务端裁剪口径改动须同步 `utils/sqlFragments.js` ↔ `supabase/functions/opendota-proxy/index.ts`（**原云函数 `aggregation/liquipedia-parse.js` 镜像已随云开发退役删除**）；④ **跨源关联用 `series_id` 比 `match_id` 可靠**。

### 3.3 对阵三态（LIVE/UPCOMING/RECENT）
- **LIVE**：开赛未结束（上限 `LIVE_STALE_MAX_SEC=3h`）；**UPCOMING**：3 天窗口 + 日期分组（dateGroup 0=今天/1=明天/2=后天）；**RECENT**：已结束，按 timeLayer 分层。
- **LIVE 卡吸收合并**：LP live/upcoming 卡吸收 OpenDota 已结算局（matchIds 硬关联 → S1 队名+时间窗第二关联键），被吸收局从 RECENT 移除防双卡。
- **★ 根因 H · `groupSeries` 强制 live**：OpenDota 对进行中 BO3 收录滞后（只返回已结算第 1 局）→ 误判 `recent`。修复：`series_type≥1` 且系列未结束且最后一场结算后 ≤6h → 强制 `isLive=true`。**BO2 特殊**：必须「打满 2 局」才算结束（不能用 `ceil(2/2)=1` 胜场条件，否则 1:0 误判已结束）；BO3/BO5 用比分达胜场条件。
- **★ 根因 I · `absorbSettledGames` S0 失败降级 S1**：LPDB v3 的 `matchIds`（`'lp_match_...'`）与 OpenDota `match_id`（数字）永不匹配 → S0 空时按格式判定：全 LPDB 字符串格式则降级 S1 队名+时间窗；含 OpenDota 数字格式保留审核 R3 `return` 保护。
- **`absorbSettledGames` S0.5 `series_id` 回退**：Steam 返回当前进行局 `match_id`、OpenDota 返回已结算局 `match_id`（同系列不同局），但 `series_id` 一致。修复：新增 `bySeriesId` 索引，S0 match_id 未全命中 + live 卡 + `series_id > 0` 时回退；仅 `phase==='live'` 生效。
- **LIVE 比分刷新**：EF `leagueMatches` TTL 5min + force 透传（30s 节流）+ 客户端低频重拉（live 120s / upcoming 60s 自适应）；explorer `teams` 表预取 resolver 解决比赛端点队名恒空。
- **Steam + haglund 并行合并**：`getScheduledMatches` 走 `Promise.all([steamPromise, liqPromise])` 按 phase 合并（Steam→LIVE / haglund→UPCOMING）；去重键 `(team1Name, team2Name, startTime)`。⚠️ 教训：降级链「短路返回」当上游只覆盖部分 phase 时会致其它 phase 永远拿不到数据。

### 3.4 缓存写穿（O-4）
- 远端成功路径 `tryCloudOrDirect` **writeThrough** 写穿本地缓存（断网/EF 熔断时兜底）。
- `ACTION_MAP` 的 path/data/ttlKey 是写穿 key 的**单一事实来源**（与 direct 侧 `cached`/`cachedFreshIncremental` 逐字符一致）。
- ⚠️ **写穿必须用 transform 前原始数据**（否则双重转换损坏）；⚠️ searchTeams 的 key 是 `|{"q":..}` 形态非 `|{}`。

### 3.5 实际开赛证据守卫（根因 J · 方案 A）

> 背景：DOTA2 赛事顺延是常态（前场 BO3 未结束 → 后场规划时间到也不会开赛），原推断默认「规划时间到 = 实际开赛」导致顺延对局被误判 LIVE。落地于 `league-detail.js` LIVE 段二次过滤 + `utils/haglund.js` 上游侧。

| 编号 | 证据 | 说明 | 适用源 |
|----|------|------|--------|
| **E1** | 系列比分非 0:0（`score1/2` 或 `scoreA/B` > 0） | 至少一局已结算 | LPDB/OpenDota 有比分 |
| **E2** | `matchIds` 含真实 OpenDota 数字 match_id（首元素 number > 0） | 已吸收局证据 | OpenDota 吸收路径 |
| **E3** | `games` 含已开赛局（`radiant_win!=null` 或 `start_time ≤ now+60s`） | 至少第 1 局已开始 | OpenDota 直连 |
| **E4** | 兜底：规划时间已过 `PROVISIONAL_GRACE_SEC=15min` | 容忍准点开赛但数据源延迟回填 | 数据源回填延迟场景 |

**防误伤**：守卫**只在「无任何证据」时**生效；E4 兜底窗防永久卡 UPCOMING；已达 BO 胜场条件的对局仍判 RECENT；覆盖全部 BO 类型。
**测试**：`scripts/test/test-postponement-guard.js`（11 场景）。

### 3.6 焦点卡 isLive 边界一致性（2026-08-23 修复「-10 天后开赛」）
- **根因**：同一 `end` 字段在「已结束」判定（`end + 86400 < nowSec`，加 1 天宽限）与 `isLive` 判定（`nowSec <= end`，未加宽限）口径不一致；`daysToStart` 无负数兜底。
- **修复**：① `isLive` 加 `end + 86400` 宽限对齐口径；② `daysToStart = Math.max(0, Math.ceil(...))`。
- **教训**：判定边界必须口径统一——同一字段在不同判定用不同宽限策略会产生状态间隙。

## 7. 安全与可观测

### 7.1 鉴权分层
- **客户端不持有真实 Supabase key**：**中转服务端注入**（`env.SB_ANON_KEY` 覆盖客户端的 `apikey`/`Authorization`）⇒ 客户端那把占位 key 无害，且**小程序包里不再有 Supabase 凭据**。
- **写权限只在 EF**：表 `curation_*` 三表 anon 只读（RLS）；写入口 = EF `admin-write`（**service key 服务端 + `x-admin-token` 鉴权**）。

## 14. 2026-10-10 变更（v9.0 · 网络阻断定论 + 中转架构）（**历史记录；网络/寻址现状以 §15 为准**）

> ⚠️ 本章为 10-10 的**架构级变更留档**。**10-13~10-16 已对本章多处事实做更新，见 §15**（尤其：主出口域名、中转断言数、`EF_ALLOW` 条目）。

### 14.1 根因定论：**域名粒度的网络阻断**
| 目标 | 现象（实测） | 结论 |
|---|---|---|
| **`*.supabase.co`** | DNS 正常但 **TLS 握手 `ECONNRESET`** | **SNI 阻断** ⇒ 换 IP / DoH / hosts 全无效，只能换域名 |
| **`api.opendota.com`** | 解析到非真实 IP + **自签证书** | **DNS 劫持** ⇒ 客户端直连废 |
| 对照 `www.opendota.com` / `dota.haglund.dev` / `liquipedia.net` / `api.stratz.com` | HTTP 200/302 正常 | **不是整片被墙，是「域名名单级」** |
| 「CI 全绿 vs App 全挂」 | CI 在**境外机房** | 域名**可达性差异**，不矛盾 |

**已排除**：白名单（已配全）、`anonKey`（真缺陷但非本次成因）、1MB 超时（92ms 就失败）、代码回归。

### 14.2 新增架构组件：**中转**（`infra/proxy/`）
```
小程序 ──HTTPS──▶ 中转域名（国内可达）       【出口在境外】
                    ├─ /sb/functions/v1/<name> ─▶ <ref>.supabase.co/functions/v1/<name>（EF，服务端注入 key）
                    ├─ /sb/rest/v1/<table>     ─▶ <ref>.supabase.co/rest/v1/<table>（PostgREST，仅 GET）
                    └─ /od/api/<path>          ─▶ api.opendota.com/api/<path>（兜底源）
```
**文件**：`worker.mjs`（核心，Web 标准 ⇒ CF Workers/Deno Deploy/Netlify Edge 通用）、`node-server.mjs`、`DEPLOY.md`（分步手册）、`test.mjs`（★ **当时 48 断言 → 现 104 断言**）。

| 设计点 | 取值 | 依据 |
|---|---|---|
| 服务端注入 key | `env.SB_ANON_KEY` 覆盖客户端 `apikey`/`Authorization` | 小程序包不再有 Supabase 凭据 |
| EF 名白名单 | ★ 原「9 个」（`opendota-proxy`/`liquipedia-proxy`/`steam-proxy`/`stratz-proxy`/`haglund-proxy`/`bundle-aggregator` + `wechat-auth`/`subscribe-send`/`follow-profile`）→ **2026-10-16 增为 10 个（+`admin-write`）** | 防被当跳板 |
| 上游超时 + 重试 | 12s + 1 次（仅 5xx/网络异常） | 单条慢上游不拖死整页 |
| GET 短路缓存 | `/proMatches` 60s、`/live` 20s、`/leagues` 30min、默认 120s | ★ TTL ≤ 客户端轮询间隔 |
| EF 白名单短缓存 | 只 `bundle-aggregator\|getLeagueDetailBundle` 60s | 详情页 bundle 单次 ~3.8s |
| 按需裁剪 | `/od/api/teams/<id>/matches` 支持 `?recent=N` 或 `X-Trim`（上限 500，**默认裁 300**，`X-Trim: 0` 显式豁免） | 全量 480KB 必超时 |

## 17. 2026-10-24：中转「陈旧兜底」+ 移除内置快照（**现行**）

### 17.1 中转「陈旧兜底」（`infra/proxy/worker.mjs`）

**问题（实测）**：上游 OpenDota 偶发「响**头很快**、**body 传输停滞**」——三轮直连实测 TTFB 1.4~2.8s，但整体 wall **2.9s / 11.1s / 30s+**。而中转原策略是 **12s 超时 × 2 次尝试 = 最坏 24s**，已超过客户端单请求 20s / 首页首屏 15s ⇒ 现象就是「打开首页对局卡十几秒」。

**改法**：
| 项 | 行为 |
|---|---|
| 触发条件 | 同一缓存键**曾成功缓存过**（即使已过期） |
| 上游尝试 | **1 次**（不再 12s×2），超时收紧到 **4s** |
| 失败兜底 | 网络异常 / 5xx / **body 读超时** ⇒ 回上一次成功响应 |
| 回执头 | `X-Proxy-Cache: STALE` + `X-Proxy-Cache-Age: <秒>`（已加入 CORS expose） |
| 无旧缓存 | **行为完全不变**（12s × 2，失败仍 502），避免把真实故障掩盖成「有数据」 |
| body 超时 | 新增 `readText(r, ms)` —— 原 `AbortController` 在响应头返回时即 `clearTimeout`，**管不到 body 停滞** |

覆盖范围：`/od/api/*` 与 `/sb/rest/v1/*`（EF 路径缓存逻辑未改）。

### 17.2 移除内置快照（用户决策）
